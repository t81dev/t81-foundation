# Proposed ADR: saved-program admission boundary

Status: **Proposed — no maintainer decision recorded**
Date: 2026-11-14
Version: proposal revision 2; canonical ADR number not assigned

## Purpose and context

Contain demonstrated old-opcode misinterpretation without reassigning opcodes,
changing execution semantics, or translating historical artifacts. At main
9256b6ec57a09e07799ae69a6f7b5467fd6ca4d2, selected-source reproductions show old
byte194 accepted as TWMATMUL by actual current raw and persisted readers. CLI
reachability is inspected; full CLI/VM execution was not reproduced. See the
[packet](../../releases/drafts/2026-11-14-opcode-boundary/README.md).

Execution descriptor is checked against the host's approved descriptor/build
association, not accepted solely because the artifact repeats a known string/hash.
Matching checksums establish identity, not authenticity. Missing or conflicting
explicit declarations reject. Producer_revision remains informational. The runtime
must not implement RFC-00D6's proposed register-indirect operations or atomic-fault
model as part of this repair.

The admission layer validates bounded representation, supported codec and binding.
It does **not** preexecute instructions, move division-by-zero/bounds/policy faults
from the VM into admission, or certify program correctness. Structural serialization
checks must be distinguished from VM operand semantics in tests. Any newly desired
semantic rejection is a separate contract decision, not implicit hardening.

## Alternatives and tradeoffs

- Global opcode remapping or guess-by-version: rejected; mapping cannot identify
  producer or settle semantic differences, and modifies historical meaning.
- Raw13 header change: rejected; breaks a frozen representation API and loses full
  Program pools, LiteralKind and i64 B when substituted for saved18.
- Manifest-only wrapper around load_program: rejected as a security completion;
  nested BigInt/tensor allocations bypass the outer count cap. Bounded parsing is
  required, or unsupported pool variants must reject explicitly.
- Leave unsafe public file APIs as an alternate default: rejected; fixing only CLI
  callers leaves the demonstrated admission path available to ordinary consumers.
- Full portable codec, legacy interpreter, new VM profile: deferred; expands this
  repair and requires independent semantics/portability decisions.

Limits intentionally narrow admission of previously accepted artifacts. They are
reviewable policy proposals, not measured universal workload requirements. Parsing
budgets do not bound VM execution, model loading or whole-process RSS. Unsupported
pool variants fail closed until their bounded decoder is qualified. No claim that
all 41 tracked legacy artifacts will execute under the new path is made.

## Approval and implementation prerequisites

Apply the separately itemized [freeze/witness plan](../../releases/drafts/2026-11-14-opcode-boundary/revision-2/FREEZE_AND_WITNESS_CHANGES.md).
Implementation requires owner acceptance of the exact wire/codec/descriptor and
resource limits; scoped breaking-change RFC/spec, migration and version plan;
freeze-exception controls for API/default/serialization impacts; and a separately
reviewed gate transition. Two reviewer approvals and an ADR do not waive an actual
unresolved determinism divergence. A major runtime recommendation is not approval.
