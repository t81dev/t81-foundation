# Investigation 09: TISC and T81Lang advantage discovery

**Status:** Proposed experiments; no comparative advantage established. Research design only.\
**Audit date:** 2026-10-27.\
**Source baseline:** Foundation [`c930b8c2ee7478782bf3c6d231bdd59984595ef2`](https://github.com/t81dev/t81-foundation/tree/c930b8c2ee7478782bf3c6d231bdd59984595ef2). All source observations below refer to this revision.\
**Decision:** Select I09-E1, an exhaustive three-state kernel equivalence and executable-footprint discriminator. Do not change the frozen ISA, add compiler features, or begin timing until equivalence passes.

## Scope and evidence rules

This proposal asks where existing instruction semantics or language constraints could help, including where conventional systems already supply the same benefit. It supports the representation research track through the implemented compiler/VM surfaces and the maintenance priorities of deterministic execution, explicit contracts, and reproducibility. It does not expand the draft network/OS architecture.

The [Master Continuity Charter](continuity/MASTER_CONTINUITY_CHARTER_v1.0.md), [Research Charter](RESEARCH_CHARTER.md), [canonical register](continuity/HYPOTHESIS_REGISTER_v1.json), and [H04-R01 discriminator](continuity/H04_RADIX_ADAPTATION_DISCRIMINATOR.md) govern interpretation. I09-H1–H4 are local investigation questions, not replacements for canonical H01–H08. No register, governance activation, frozen instruction, or historical result is changed here.

Use the continuity evidence tiers: A = reproduced execution, B = inspected source, C = historical report, D = mathematical/model deduction, E = speculation. A specification establishes a requirement, not an implementation result. A test file establishes available coverage, not that it passed. This audit inspected source and existing evidence; it did not run new compiler conformance, differential workloads, or benchmarks. The sole executed repository check was the freeze-integrity script, whose bounded result is recorded below.

“Advantage” must name its dimension: language expression, encoded executable size, live state, compiler work, host execution time, assurance, or physical hardware cost. These dimensions are not interchangeable. A smaller number of high-level instructions can conceal allocation, conversion, policy, or serialization work.

## Historical continuity and existing counterevidence

The [source-grounded lineage](continuity/LINEAGE.md) pins the Hanoi CWEB archive in Foundation at `fe00396831c8bb249fde06a04186fa02f6018caf` and the current public Hanoi import at `59205d76db4aca3da7c0bdc521924b8f9bc52cc3`. The compiler split is supported by parser blob identity, not by a claim that entire toolchains remain equivalent. Knuth, discrete mathematics, recursion, and CWEB are the stated intellectual origins; the unavailable original paper/PDF and private chronology remain historical reports.

The [isolated historical arithmetic source](continuity/evidence/isolated_hanoi_arithmetic.c) visibly normalizes addition into 0/1/2 and multiplies components independently. The [recorded oracle results](continuity/evidence/hanoi-arithmetic-results.json) report 422/547 addition failures and 140/201 multiplication failures against positional integers in the representable range [-13,13], with 0/27 negation failures. These are prior recorded results, not reruns here. They disqualify substituting componentwise algebra for integer arithmetic; they do not falsify all three-state algebras or modern Foundation arithmetic.

Hanoi's 81/243/729 scheduler labels do not establish precision domains or physical widths. Modern tier limits are recursion/resource policy. Base-81's four-trit grouping does not by itself save binary-host storage. I09-H3 therefore inherits H04-R01's exact-domain and adaptive-binary controls rather than assuming an operational historical radix selector.

The canonical register's H04-R01 entry predates the current [`H04-R02` packet](../../experiments/h04_r02_adaptive_representation/). That packet is present on the audited main revision; do not describe it as missing. Its “Complete / Final” label and [verification guide](../../experiments/h04_r02_adaptive_representation/VERIFICATION.md) are reported evidence, not this audit's reproduction. Two source-level obstacles prevent adopting its crossover conclusions:

- [`main.cpp`, lines 90–94](https://github.com/t81dev/t81-foundation/blob/c930b8c2ee7478782bf3c6d231bdd59984595ef2/experiments/h04_r02_adaptive_representation/main.cpp#L90) computes the total break-even using binary transition/selector terms and divides by ternary symbol slots. It does not solve its own ternary metadata-dependent cost expression.
- [`adaptive_experiment.hpp`, lines 145–179](https://github.com/t81dev/t81-foundation/blob/c930b8c2ee7478782bf3c6d231bdd59984595ef2/experiments/h04_r02_adaptive_representation/adaptive_experiment.hpp#L145) scales ternary metadata by C3/C2 despite naming it bits, and adds selector/conversion and transition proxy costs. These are model assumptions, not measured CPU time. The ledger inspects supplied values; it does not establish compiler-driven arithmetic execution cost.

For its declared model, write `AB = sB + mB + tB + nB*c` and `AT(r) = (sT + mT)*r + tT + nT*c`. The crossover is `(AB - tT - nT*c)/(sT + mT)`, when the denominator is positive, not the implemented expression. If metadata stays binary in both arms, it needs a different expression. This is an algebraic audit observation (D), not a corrected measurement. Preserve the existing packet unchanged and require an independently checked ledger before using it in I09-H3. No canonical status is advanced here.

External comparator semantics were consulted on 2026-10-27: [LLVM 21.1.0 Language Reference](https://releases.llvm.org/21.1.0/docs/LangRef.html), [WebAssembly instruction specification, page labeled 3.0 / 2026-10-23](https://webassembly.github.io/spec/core/syntax/instructions.html), and [GNU MP 6.3.0 arithmetic](https://gmplib.org/manual/Integer-Arithmetic). Do not compare TISC instructions numerically with Wasm stack operations, LLVM IR operations, or native instructions as though each had equal cost. Do not use a deliberately naive binary interpreter as the only baseline.

## Shared experimental contract

The following applies to every protocol. It is a future execution plan, not a claim that a harness or result already exists.

1. Pin source SHA, dirty-tree status, build cache/options, compiler/linker/runtime versions, dependency hashes, CPU/OS/architecture, available memory, optimization flags, deterministic math settings, backend, policy and workload seed. Capture effective flags: repository defaults can add optimization and `NDEBUG`; cache build type alone is insufficient.
1. Define mathematical values, input domain, overflow/promotion, division and malformed-input behavior, output order, side effects, policy decisions, and evidence/replay contracts. Independently compute the oracle. Require **zero unexplained differences** in outputs, intermediate values, traps and required effects before any timing. Compare semantic state projections, not unrelated register numbering.
1. Generate workloads before inspecting cost outcomes. Preserve all cases, compiler failures and negative controls. Separate trusted typed inputs from untrusted input validation; charge equivalent checks on both sides.
1. Use independent temporary directories and empty stores per cold observation; record actual emptiness. Declare separate populated-store and warm-session conditions. Never reuse an artifact cache silently. OS page-cache coldness is not established by an empty directory.
1. For timed extensions, use 5 excluded warmups per warm arm and 30 paired observations with a seeded randomized order on one idle host. Collect cold and warm series separately. Store raw observations and output fingerprints. Report medians, paired ratios and a paired-bootstrap 95% interval with a pinned seed; do not stop early on significance. Repeat on a second architecture before making portability claims.
1. Attribute process initialization, parse/compile, decode/load, representation conversion, computational execution, policy evaluation, evidence construction/persistence, independent artifact retrieval, replay and verification separately wherever observable. Publish wall-clock end-to-end totals. Nested inclusive/exclusive timers must reconcile; unobservable residuals stay unattributed. Static instruction counts and model units have no confidence interval masquerading as timing uncertainty.
1. Equalize guarantees before comparing assurance costs. If a trace of every semantic step is required, the conventional control must provide that trace, not merely final effect logging. If equivalent event mapping is unavailable, mark the comparison ineligible. Semantic artifact references may differ by encoding; each must independently recover and verify its claimed bytes and model/configuration identity.
1. Persist exact commands, sources, inputs, generated artifacts/IR/disassembly, logs, failures, raw metrics, schema and an independent reproduction recipe. An independent fresh process must recover from recorded references without hidden overrides when recovery is required. Preserve older evidence as historical/invalidated/superseded with reasons. No embedded expected timings or invented samples.

Performance thresholds below are preregistration choices, not predictions. A passing comparison supports only its named workload/domain/profile. A failed narrow comparison does not prove that every future ternary implementation must fail.

Logical live state means the maximum simultaneously needed semantic values and their declared payload widths at the kernel boundary/steps. Physical register arrays, tags, Wasm operand stack and runtime allocation are additional measured quantities. A payload win accompanied by larger actual resident state must be disclosed and cannot become a total-memory claim. TISC condition flags and auxiliary state matter if consumed by the program; the oracle must include them in the same-VM attribution control.

This is intentionally capable of returning a negative result quickly: conventional min/max and negation already express these semantics compactly. A footprint benefit, if found, would be real but narrowly about artifact encoding. Even a dramatic win would leave host execution and native ternary hardware efficiency unproven.

Workload family           | Pure repeated expressions, known-shape vector construction, Option/Result access; negative controls with mutation, indirect effects through a helper, dynamic shapes, aliasing and unreachable branches. Publish a fixed 12-program matrix: one positive and one violating case for each of six constraints (binding immutability, fixed shape, numeric widening, direct-effect purity, helper-call purity, and short-circuit effect order). Repeated expressions and Option/Result access supply common computation inside those programs. |
| 4. Primary metric            | Number of required runtime validation sites remaining after lowering at matched acceptance/guarantee coverage. Report compile+verification wall time, emitted bytes and execution time separately; diagnostic quality and fewer source statements are not the metric.                                                                                                                                                                                                                                                                       |
| 5. Required controls         | Typed C++ enum/variant and checked functions; Clang/LLVM at O0/O2/O3 with identical range/effect facts. Compare T81 default path and only semantically supported optional MLIR subsets. Attribute CSE/SSA improvements to the common optimizer unless source constraints supply independently verified information.                                                                                                                                                                                                                         |
| 6. Confounders               | Different static expressibility, unchecked conventional APIs, pure annotations without transitive proof, constant input elimination, frontend maturity, duplicated checks moved to runtime, unsupported instructions silently omitted.                                                                                                                                                                                                                                                                                                      |
| 7. Falsification             | A missing required check/effect is a defect, not optimization. At matched coverage, equal or greater required runtime checks falsify this suite's check-elimination advantage. A cost gain disappearing when conventional facts match is not a unique language benefit.                                                                                                                                                                                                                                                                     |
| 8. Minimum useful experiment | First examine a pure function calling an effectful helper, direct effect rejection, and a truly pure helper. Verify analyzer output and runtime trace. This three-case feasibility gate can disqualify purity-based optimization without implementing a new pass; only proceed to the 12-case suite if the claimed constraint is actually enforced.                                                                                                                                                                                         |
| 9. Stopping criteria         | Stop a constraint arm on unsound acceptance/reordering, missing lowering or inability to give the comparator equivalent facts. Finish the fixed matrix for remaining eligible constraints; do not add an optimizer to rescue results. No broad language advantage from one successful literal-construction case.                                                                                                                                                                                                                            |

## Priority and execution decision

Ordinal scores below are judgment for scheduling, not experimental evidence. “High” falsifiability means a small counterexample can invalidate the bounded claim; effort includes a competent comparator.

| Rank | Experiment                       | Information gained                                                | Existing-code feasibility                                  | Falsifiability                                                 | Hypothetical hardware dependence                       | Estimated effort                                           | Hanoi/T81 objective relevance                     |
| ---- | -------------------------------- | ----------------------------------------------------------------- | ---------------------------------------------------------- | -------------------------------------------------------------- | ------------------------------------------------------ | ---------------------------------------------------------- | ------------------------------------------------- |
| 1    | E1: finite three-state footprint | High: separates fused semantics from realized encoding/state cost | High; existing scalar lowering/dispatch; Wasm tools needed | High; exhaustive domain and exact artifacts                    | None                                                   | Small driver and conventional kernels                      | Direct three-state/H02/H05 link                   |
| 2    | E3: independent H04 ledger       | High: checks a live quantitative claim and baseline fairness      | High for model audit; low for realized compiler selection  | High for algebra/domain, limited for physical performance      | None for audit; high if extrapolated to native devices | Small audit; substantially larger realized selector        | Strongest original adaptation/H04 continuity      |
| 3    | E2: constraint/optimization gate | High negative-information potential                               | Medium; partial effect proof and backend gaps              | High for unsound constraint, moderate for optimization benefit | None                                                   | Small feasibility probe; medium matched matrix             | Language and accountable-computation extension    |
| 4    | E4: equal-assurance workflow     | High but costly to establish comparability                        | Medium/low before a matched trace/replay contract          | High correctness; harder cost attribution                      | None                                                   | Largest: conventional composition and independent verifier | Modern H07 continuation, not precision adaptation |

Execute **E1 only as the next proposed work package**. It is the smallest complete discriminator with an exhaustive mathematical domain, a real existing TISC/compiler path, and exact resource measurements. E3 is a valuable subsequent audit but cannot currently establish compiler-aware selection. E2's three-case purity probe is smaller than E1 but can only reject an optimization premise; it cannot demonstrate the requested realized resource advantage. E4 requires more assurance engineering before its cost comparison is fair.

The first E1 decision is binary about eligibility: can every required artifact execute equivalently after independent reload? The second is the preregistered footprint/state comparison. Neither authorizes a claim about native speed. A later optimized conventional native run versus an interpreted T81 run would be an **implementation comparison**, with architecture superiority **INCONCLUSIVE**. A fair architectural performance claim needs comparable optimization/runtime conditions or a justified cost model including their differences; this proposal supplies neither measured superiority nor a hardware model.

## Review and release gate

A future execution packet must contain the pinned manifest, exact inputs/oracle, actual artifacts, intermediate parity and guarantee results, raw cost ledgers, commands, uncertainty and negative findings before any advantage claim is accepted. Zero unexplained valid-domain differences is mandatory. Missing baselines, silent backend omissions, incomparable guarantees or unexplained residual costs keep the relevant question inconclusive. Preserve the old evidence with explicit disposition rather than rewriting it.

This PR contains this design document only. It does not implement or run E1–E4, add instructions or optimizations, change the H01–H08 register, merge pending investigations, or declare Investigation 09 complete. Review of this proposal should assess whether the protocols can expose failure as readily as success.
