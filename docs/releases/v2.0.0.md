**Date:** 2026-11-17  
**Tag:** `v2.0.0` (release candidate qualification on `main`)

T81 Foundation `v2.0.0` aligns project packaging, public API version metadata, SDK header installation, and deterministic runtime/interchange hardening into a single major-version baseline.

T81 remains an experimental computing research platform. This release does not establish production readiness, native ternary hardware advantage, or broader determinism guarantees beyond the tested surfaces.

## Compatibility and Breaking Changes

- **Version & Public API Baseline (`2.0.0`):** `CMakeLists.txt`, `pyproject.toml`, `include/t81/config.hpp`, and `PUBLIC_API_LOCK.json` are aligned to `2.0.0`.
- **CanonFS Persistent Stores:** Portable storage uses `h1-` lowercase-hex filename components and `.canonfs-format = t81-canonfs-hex-v1`. Unmarked nonempty legacy stores are rejected with an explicit migration error; back up stores and capability metadata before migrating.
- **Bytecode & C++ ABI:** Extension/vector/FFI opcode assignments and `T81Fraction` exception-safety/class layouts changed relative to `v1.9.4`. Recompile bytecode artifacts and C++ consumers against matched `v2.0.0` headers and libraries.
- **Policy Hooks:** `AxionVerdict` defaults to deny; policy hooks must return an explicit allow verdict after checks.

## Key Engineering & Hygiene Changes

- **VM & Runtime Hardening:** Integer arithmetic UB guards and Tier 6 rank mapping (`#798`), `--canonfs-root` CLI contract isolation and `canonfs export --policy-profile` negative testing (`#830`).
- **SDK & Packaging Hygiene:** Excluded `config.hpp.in` and `config.hpp.backup` from `cmake --install` header trees (`#832`), fixed `Dockerfile` script copy path (`#829`), and aligned GitHub Actions / CodeQL pins (`#832`).
- **Documentation & Governance:** Consolidated root research/capabilities reports into `docs/research/` (`#833`), reconciled `CURRENT_STATE.json` and `START_HERE.md` (`#830`), and added non-publishing `workflow_dispatch` dry-run guards to release/wheel/Docker workflows (`#833`, Batch 5).

## Verified Capabilities vs. Current Boundaries

### What `v2.0.0` Accomplishes Today

- **Deterministic Balanced-Ternary VM & ISA (`TISC` + `T81VM`):** Balanced-ternary numeric and tensor types (`T81Int`, `BigInt`, `T81Float` soft-float, `Fraction`, `Tensor1D3`, `Tensor2D33`, `T729DynamicTensor`, `T729IntTensor`) with CI-verified bit-exactness and scalar/SWAR/AVX2/NEON equivalence ([Determinism Surface Registry](../governance/DETERMINISM_SURFACE_REGISTRY.md)).
- **Bounded Cross-Profile Execution (CPA-004/CPA-005):** Identical execution of a frozen 351-byte canonical TISC subset across hosted `T81VM` and bare-metal AArch64 QEMU (`Axion OS / TernaryOS` after UEFI `ExitBootServices`) across all 25 observation boundaries.
- **CLI & Python Tooling:** Unified `t81` CLI (`code`, `lang`, `project`, `repl`, `vm`, `tisc`, `ir`, `trace`, `studio`, `agent`, plus experimental `llvm`/`mlir` and `c`/`rust`/`python` subset-to-MLIR bridges) and Python bindings (`ffi/python/`) exposing `compile()`, `compile_and_run()`, `VM()`, numeric/tensor types, and CanonFS drivers.
- **Axion Policy & Audit:** Fail-closed pre-side-effect policy enforcement and deterministic audit trails (`t81 policy`, `t81 axion`, `t81 trace`, `vm.axion_log`).
- **CanonFS & RFC-00D1 v1 Interchange Seed:** Content-addressed immutable storage and `t81 canonfs` host-file/host-directory import/export with v1 JSON result, provenance, and manifest schemas (`t81.canonfs-import.v1`, `t81.canonfs-export.v1`, etc.) and operation-level policy profiles.
- **Bounded AI & Model Surfaces:** Model weights inspection and execution via `t81 weights`, `t81 code run ... --weights-model ...`, and `t81 internal llama-run ...`; strict deterministic `t81 ai inference run` on the `t81_reference_vm` probe (4-step `forward_state` + hidden-tensor export/reimport); and the frozen 3-member bounded AI OS-object family (`assess-fixed`, `route-fixed`, `classify-fixed`).

### Explicit Non-Claims and Draft/Experimental Boundaries

- **Not a general native AI inference runtime:** Non-`t81_reference_vm` backends in `t81 ai inference run` remain scaffolded, and the bounded AI OS-object family is frozen at 3 compositions (not a workflow or orchestration engine).
- **No established ternary speed or hardware advantage:** Historical AVX2 matvec favored native INT8 over packed 2-bit ternary (17.15 vs. 12.91 GFLOP/s), `T81-AIOPT-001` M1 was falsified as reducible to a scalar lookup, and physical ternary silicon (Investigation 10A) remains unmeasured/blocked.
- **Draft & unverified subsystems:** `RFC-00D0` (base-81 TCP/IP) is design-led; `RFC-00D2` (DAIOS) is an architecture sequencing note; Trace-JIT equivalence, distributed cognitive tiers, external accelerators, and bare-metal `TernaryOS` remain experimental/unverified outside the Determinism Surface Registry.
