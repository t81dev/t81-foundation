## 2.1 确定性不变性

**状态：已实现并测试**

T81 架构的中心公理是**严格的确定性**。在这个系统中，程序 $P$ 不是对硬件的建议；它是状态转换函数 $f$ 的数学定义。

形式上，给定初始状态 $S$ 和输入向量 $I$，函数必须满足：
$$
\forall \text{hardware } H: \text{Exec}_H(S, I) \to S' \implies S' \text{ is invariant}
$$

实现这一点需要消除现代计算中所有常见的非确定性来源。T81 将宿主环境（OS、CPU、FPU）视为必须加以限制的“对抗性熵源”。

### 2.1.1 确定性表面与攻击向量

“确定性表面”是抽象机器与物理现实交互的边界。任何物理现实（时间、随机噪声、硬件怪癖）泄露到逻辑状态中都构成**确定性破坏**。

| 层级 | 确定性风险 | 缓解措施 | 实现证据 |
| :--- | :--- | :--- | :--- |
| **编译器** | 令牌顺序、Map 迭代 | 规范 AST 排序 | `src/frontend/ast.cpp` (Sorted Maps) |
| **VM 内存** | 指针地址泄露 | 不透明句柄 (Indices) | `src/vm/vm.cpp` (Memory Segments) |
| **垃圾回收** | 非确定性回收周期 | 分配计数触发 | `src/vm/gc.cpp` (Instruction-based GC) |
| **并发** | 竞争条件、调度 | 协作协程 | `src/vm/scheduler.cpp` (Deterministic Ticks) |
| **浮点** | 宿主 FPU 漂移 (IEEE-754) | `dmath` 软件浮点 | `include/t81/core/T81Float.hpp` |
| **超越函数** | Libm 实现差异 | 泰勒级数 (Fixed iter) | `include/t81/core/detail/dmath.hpp` |
| **JIT** | 优化分歧 | 追踪等效性检查 | `src/vm/jit_compiler.cpp` |

### 2.1.2 “Libm 差距”与 `dmath`
跨平台确定性中的一个关键漏洞是“Libm 差距”。IEEE-754 标准定义了浮点格式，但对超越函数（sin, cos, pow）的规定很宽松。因此，x86_64/GLIBC 上的 `std::sin(x)` 可能与 ARM64/MUSL 上的 `std::sin(x)` 相差 1 ULP（最后一位单位）。

T81 通过 **`dmath`** (确定性数学) 解决了这个问题，这是一个自定义库，实现了：
*   **软浮点算术**：`Add`, `Sub`, `Mul` 是位精确的。
*   **自定义超越函数**：`Sin`, `Cos`, `Exp` 通过具有固定迭代次数和固定常数的泰勒/麦克劳林级数实现，忽略主机的 `libm`。
*   **舍入模式**：在软件中强制执行偶数舍入 (Ties-to-even)。

> **不变性**：$\text{dmath::sin}(x)$ 在 Intel i9、Apple M3 和 RISC-V 开发板上产生完全相同的位模式。

## 2.2 三进制逻辑 (Base-3)

**状态：已实现并测试**

T81 是一个**平衡三进制**系统。基本单位是 **trit**，值为 $\{-1, 0, 1\}$（通常表示为 $-, 0, +$ 或 $T, 0, 1$）。

### 2.2.1 为何选择三进制？
1.  **对称算术**：取值范围关于零对称。在二进制（补码）中，范围是不对称的（例如，-128 到 +127）。在平衡三进制中，$N$-trit 整数覆盖 $-\frac{3^N-1}{2} \dots +\frac{3^N-1}{2}$。
2.  **舍入效率**：四舍五入到最近整数等同于截断。$0.5$ 无法精确表示，避免了“0.5 舍入问题”。
3.  **基数经济性**：当 $r = e \approx 2.718$ 时，基数经济性 $E(r, N) = r \lfloor \log_r N \rfloor$ 最小。整数 $3$ 比 $2$ 更接近 $e$，使得三进制在理论上对于信息存储密度更有效。
4.  **有符号表示**：负数不需要单独的符号位。符号由最高非零 trit 携带。

### 2.2.2 实现
在 C++ 代码库中，trits 为了效率在二进制硬件上进行模拟。
*   **打包存储**：`T81Int` 使用每 trit 2 位编码方案（00=0, 01=1, 11=-1/T）。这允许 4 个 trits 放入一个字节（一个 Tryte）。
*   **算术**：操作使用模拟平衡三进制进位链的整数数学实现。
    *   示例：$1 + 1 = 1T$ (即 $3 - 1 = 2$)。
    *   示例：$T + T = T1$ (即 $-3 + 1 = -2$)。

## 2.3 可审计性与 Axion 追踪

**状态：已实现并测试**

仅仅有确定性是不够的；执行必须是 **可审计的**。Axion 内核生成一个称为 **追踪 (Trace)** 的加密日志。

### 2.3.1 追踪结构
追踪 $\mathcal{T}$ 是事件 $E_0, E_1, \dots, E_k$ 的有序序列。每个事件捕获一个重要的状态转换或策略检查。

```cpp
struct AxionEvent {
    uint64_t tick;          // 逻辑时间戳
    Opcode op;              // 尝试的操作码
    Verdict verdict;        // 内核的决定 (Allow/Deny)
    CanonHash81 state_hash; // VM 状态的 Merkle 根
    std::string metadata;   // 上下文调试信息
};
```

此追踪充当 **执行证明**。通过针对初始状态重放追踪，审计员可以在不信任产生结果的硬件的情况下，数学上证明计算产生了声称的结果。

## 2.4 九项原则 (伦理强制执行)

**状态：已实现并测试**

T81 将一套不可变的“宪法原则”（$\Theta_1 \dots \Theta_9$）直接嵌入到 VM 的策略引擎中。这些不仅仅是指导方针；它们是 Axion 内核强制执行的运行时约束。

| 符号 | 原则 | 描述 | 强制执行者 |
| :--- | :--- | :--- | :--- |
| $\Theta_1$ | **无害 (Non-Harm)** | 基础安全层；防止内存损坏和段错误。 | 内存边界检查 |
| $\Theta_2$ | **非胁迫 (Non-Coercion)** | 防止未经加密授权的强制状态转换。 | 签名验证 |
| $\Theta_3$ | **真理 (Truth)** | 信息必须是规范的；两个不同的哈希不能映射到同一个对象。 | CanonFS 碰撞检查 |
| $\Theta_4$ | **可解释性 (Interpretability)** | 警告不透明的“黑盒”执行；第 3 层及以上强制生成追踪。 | 追踪记录器 |
| $\Theta_5$ | **身份完整性 (Identity Integrity)** | 分布式节点必须维护一致的身份密钥。 | 第 4 层握手 |
| $\Theta_6$ | **伦理优先 (Ethical Priority)** | 安全策略覆盖性能优化。 | 策略抢占 |
| $\Theta_7$ | **熵遏制 (Entropy Containment)** | 防止无限制的资源扩展（例如，无限循环、内存泄漏）。 | 递归限制 / Gas |
| $\Theta_8$ | **规范一致性 (Canonical Consistency)** | 所有数据在哈希之前必须标准化。 | 序列化器 |
| $\Theta_9$ | **透明执行 (Transparent Execution)** | 系统不得隐藏副作用；`MetaWrite` 需要明确的策略许可。 | Axion 拦截器 |

> **示例**：如果程序尝试无限递归，它违反了 $\Theta_7$（熵遏制）。Axion 内核检测到 `recursion_depth > policy.max_depth` 并发出 `Deny` 裁决，将操作转换为 `Trap::SecurityFault`。
