## 14.1 无尘室协议

**状态：愿景**

T81 项目的设计采用了 **“文明尺度”** 的思维方式。目标是，如果所有源代码存储库（GitHub、GitLab、PyPI）都消失了，该系统可以从这本专著和标准的 C++ 编译器规范中重建。

### 14.1.1 重建步骤
1.  **检索**：获取 **权威技术专著**（本书）的副本。
2.  **验证**：根据已知的数学常数确认核心算法（SHA3-256，平衡三进制算术）的加密哈希。
3.  **实现**：
    *   编写一个符合 C++23 标准的编译器。
    *   根据第 4 章中的位布局规范实现 `T81Int` 和 `T81Float`。
    *   实现 TISC VM 指令循环（第 3 章）。
    *   实现 Axion 策略逻辑（第 8 章）。
4.  **验证**：运行附录中包含的或根据描述重建的测试套件 (`tests/cpp/*.cpp`)。

## 14.2 单点故障

**状态：已缓解**

T81 识别并减轻了对中心化基础设施的依赖。

*   **源代码控制**：仓库镜像在多个 git 锻造平台（GitHub、GitLab，甚至可能是 IPFS）上。
*   **构建工具**：CMake 是标准构建系统，但项目结构足够简单，可以手动编译或使用 shell 脚本。
*   **依赖项**：除了 C++ 标准库之外，T81 **没有必需的运行时依赖项**。它自行维护关键组件（如用于网络的 `asio`）或从头实现它们（如用于超越函数的 `dmath`）。

## 14.3 持续性清单

**状态：已记录**

以下工件构成了重建 T81 所需的“持续性工具包”：

1.  **书**：`docs/developer-guide/book/book-cn/*.md`（本文档）。
2.  **规范**：`spec/*.md`（正式的 TISC/Axion 规范）。
3.  **代码**：`src/` 和 `include/`（参考实现）。
4.  **测试**：`tests/cpp/`（验证逻辑）。
5.  **脚本**：`scripts/ci/`（重现网关）。

## 14.4 不可变的形式不变量

**状态：永恒**

无论实现细节如何（C++、Rust、Zig），任何自称为“T81”的系统都必须遵守这些不变量：

1.  **严格的确定性**：$f(S, I) \to S'$ 在跨平台时是位精确的。
2.  **原生三进制**：逻辑是 base-3 的。
3.  **策略强制**：没有 Axion 批准，任何指令都不能执行。
4.  **结构诚实性**：没有显式类型就没有近似值。

如果一个系统违反了其中任何一条，它就是一个分叉，而不是 T81。
