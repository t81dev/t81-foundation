## 8.1 形式化验证方法论

**状态：已实现**

T81 采用多层验证策略，从单元测试到形式化属性验证。

### 8.1.1 验证栈

1.  **单元测试 (L1)**：检查单个函数和类。
    *   示例：`tests/cpp/test_T81Int.cpp` 验证 `T81Int::add(1, 1) == 1T`。
2.  **基于属性的测试 (L2)**：生成随机输入以验证不变量（QuickCheck 风格）。
    *   示例：`tests/cpp/test_property_invariants.cpp` 验证 $\forall a, b: a + b = b + a$。
3.  **模糊测试 (L3)**：向解析器和 VM 提供畸形输入，以确保崩溃恢复能力。
    *   示例：`tests/cpp/frontend_fuzz_test.cpp` 使用 `libFuzzer`。
4.  **集成测试 (L4)**：运行完整的端到端程序并验证输出。
    *   示例：`tests/cpp/e2e_arithmetic_test.cpp`。
5.  **确定性网关 (L5)**：验证跨环境的位精确可重现性。

## 8.3 基于属性的测试

**状态：已实现**

我们使用 **基于属性的测试 (Property-Based Testing)** 来证明代数定律对我们自定义的数值类型成立。

### 8.3.1 环公理 (The Ring Axioms)
文件 `tests/cpp/test_property_invariants.cpp` 编程验证 `T81Int` 和 `T81Float` 满足环的公理：
1.  **结合律**：$(a + b) + c = a + (b + c)$
2.  **交换律**：$a + b = b + a$
3.  **单位元**：$a + 0 = a$
4.  **逆元**：$a + (-a) = 0$
5.  **分配律**：$a \times (b + c) = (a \times b) + (a \times c)$

这些测试使用随机输入（包括 `MaxInt`, `MinInt`, `Zero` 等边缘情况）运行数百万次迭代，以提供对正确性的高统计置信度。

## 8.4 确定性网关

**状态：活跃**

**确定性网关** (`scripts/ci/t81lang_repro_gate.py`) 是任何代码合并前的最终检查。

### 8.4.1 机制
1.  **编译一致性**：它将一组 5+ 个规范的夹具程序 (`*.t81`) 编译两次。它比较 Pass A 和 Pass B 的二进制输出。任何位差异都会导致立即失败。
2.  **聚合哈希**：它计算所有夹具生成的字节码的 SHA-256 哈希值。
3.  **基线验证**：此聚合哈希与签入的“黄金哈希”进行比较。如果编译器逻辑发生变化（导致不同的字节码），哈希值将漂移，构建将失败。这确保了编译器更改是有意且经过审计的。

### 8.4.2 可追溯性
当网关通过时，它输出：
```text
[PASS] T81Lang gates passed: fixtures=5 hash=a7f92b...
```
此哈希值记录在 CI 日志中，为该版本的编译器状态提供不可变的记录。
