## 9.1 Формальное определение

**Статус: Реализовано и протестировано**

**Ядро Axion** — это страж рантайма T81. В отличие от традиционных операционных систем, где безопасность обеспечивается на границе системных вызовов (переключение режима пользователя/ядра), Axion обеспечивает безопасность на **уровне инструкций**.

Формально Ядро Axion — это функция $\alpha$, которая отображает текущее состояние машины $S$ и предлагаемую операцию $Op$ в вердикт $V$:
$$
\alpha: (S, Op) \to \{\text{Allow}, \text{Deny}, \text{Warn}, \text{Defer}\}
$$

Эта оценка происходит **до** того, как произойдет переход состояния $S \xrightarrow{Op} S'$. Если $\alpha(S, Op) = \text{Deny}$, переход прерывается, и машина вызывает прерывание `SecurityFault`.

## 9.2 Модель политик

**Статус: Реализовано**

Политики — это декларативные наборы правил, которые определяют ограничения для конкретного контекста выполнения. Политика говорит не о том, *что* вычислять, а о том, *как* это разрешено вычислять.

### 9.2.1 Язык политик (S-выражения)
Политики Axion определяются с использованием синтаксиса S-выражений (подобного Lisp), что обеспечивает легкий парсинг и канонизацию.

**Пример: Строгая политика Уровня 1**
```lisp
(policy
  (tier 1)                  ; Ограничить Символьным уровнем (Нет рекурсии, нет рефлексии)
  (max-instructions 10000)  ; Жесткий лимит газа
  (max-stack 256)           ; Лимит глубины стека
  (max-tensors 0)           ; Аллокация тензоров запрещена
  (allowed-tensor-hashes []) ; Внешние веса запрещены
)
```

**Пример: Политика ИИ-инференса Уровня 3**
```lisp
(policy
  (tier 3)
  (max-recursion 1024)
  (max-tensors 50)
  (max-tensor-elements 1000000)
  (allowed-tensor-hashes [
    "canon:sha3:a7f..." ; Конкретные разрешенные веса моделей
  ])
)
```

### 9.2.2 Возможности (Capabilities)
Возможности — это гранулированные права, предоставляемые процессу.
*   **NetAccess**: Возможность использовать хендлы `IoNet` (Уровень 4).
*   **MetaWrite**: Возможность изменять сегмент Meta (Рефлексия).
*   **InfExpand**: Возможность инстанцировать бесконечные формы (Уровень 5).

## 9.3 Перехват инструкций

**Статус: Реализовано и протестировано**

Ядро Axion интегрировано непосредственно в цикл выборки-декодирования-выполнения VM.

### 9.3.1 Хук перехватчика
В `src/vm/vm.cpp` основной цикл вызывает движок политик:

```cpp
// Псевдокод цикла интерпретатора
while (!halted) {
    Opcode op = fetch();

    // 1. Проверка Axion
    Verdict v = axion->evaluate(ctx);
    if (v == Verdict::Deny) {
        throw SecurityFault(v.reason);
    }

    // 2. Выполнение
    execute(op);

    // 3. Журналирование аудита
    if (v == Verdict::Warn || policy.audit_all) {
        trace.log(op, v, state_hash);
    }
}
```

### 9.3.2 Абстракции с нулевой стоимостью?
Нет. T81 явно отвергает "Абстракции с нулевой стоимостью", если они ставят под угрозу безопасность. Проверка Axion накладывает накладные расходы на производительность. Это осознанный выбор дизайна: **Корректность > Производительность**. Однако для JIT-скомпилированных трасс проверки политик выполняются один раз во время записи трассы и встраиваются в оптимизированную трассу как охраняемые утверждения, что значительно снижает накладные расходы во время выполнения.

## 9.4 Журнал аудита (Трасса)

**Статус: Реализовано и протестировано**

**Трасса** — это криптографическое доказательство того, что произошло. Это не просто журнал отладки; это цепочка событий Меркла.

### 9.4.1 Структура трассы
Каждая запись в журнале содержит:
1.  **Tick**: Логическое время.
2.  **Opcode**: Выполненная инструкция.
3.  **Verdict**: Решение Axion.
4.  **StateHash**: Хэш SHA3-256 релевантного состояния машины *после* операции.

$$
H_{t} = \text{Hash}(H_{t-1} || \text{Op}_t || \text{Verdict}_t || \text{StateDiff}_t)
$$

Финальный хэш $H_n$ — это **Доказательство выполнения**. Если две стороны запускают один и тот же код и получают один и тот же $H_n$, они криптографически гарантированно достигли абсолютно того же состояния абсолютно тем же путем.

## 9.5 Когнитивное продвижение

**Статус: Реализовано**

Программа начинается на определенном Когнитивном Уровне (обычно Уровень 1). Она может запросить **Продвижение** (Promotion) на более высокий уровень для выполнения более сложных операций.

*   **Запрос**: Программа выполняет опкод `Promote` с подписанным токеном возможности.
*   **Оценка**: Axion проверяет токен на соответствие политике.
*   **Результат**: Если разрешено, `tier_status` VM обновляется, разблокируя новые опкоды (например, `Recurse` или `Gossip`).

**Путь эскалации уровня**:
1.  **Уровень 1**: Безопасный, ограниченный, полиномиальное время.
2.  **Уровень 2**: Динамичный, рефлексивный.
3.  **Уровень 3**: Рекурсивный, потенциал экспоненциального времени (требует лимитов газа).
4.  **Уровень 4**: Нелокальный, сетевой (требует лимитов консенсуса).
5.  **Уровень 5**: Бесконечный (требует строгого сдерживания).

> **Верификация**: `tests/cpp/test_ethics.cpp` проверяет, что попытки использовать опкоды Уровня 3 в политике Уровня 1 приводят к `SecurityFault`.
