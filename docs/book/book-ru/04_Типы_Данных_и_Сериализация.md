## 4.1 Примитивные типы

**Статус: Реализовано и протестировано**

Архитектура T81 построена на фундаменте сбалансированных троичных примитивов. Эти типы спроектированы для эффективной эмуляции на двоичном оборудовании при сохранении математических свойств логики по основанию 3.

### 4.1.1 Триты и трайты

*   **Трит**: Фундаментальный атом информации, принимающий значения $\{-1, 0, 1\}$.
    *   Также обозначается как $\{T, 0, 1\}$ или $\{-, 0, +\}$.
    *   Информационное содержание: $\log_2 3 \approx 1.58$ бит.
*   **Трайт**: Последовательность тритов. Стандартный "эквивалент Байта" — это трайт из 4 тритов ($3^4 = 81$ значений).
*   **Слово (Word)**: Стандартное машинное слово T81 состоит из 27 тритов ($3^{27} \approx 7.6 \times 10^{12}$), что комфортно помещается в 64-битное целое число.

**Упакованное представление (T3_K)**:
Для эффективного хранения триты часто упаковываются с использованием 2-битного кода:
*   `00` $\to$ 0
*   `01` $\to$ 1
*   `10` $\to$ -1 (T)
*   `11` $\to$ Не используется / Заполнение

### 4.1.2 T81Int (Целое число произвольной точности)
`T81Int` — это целочисленный тип переменной ширины. В отличие от двоичных целых чисел, использующих дополнительный код для отрицательных значений, сбалансированные троичные целые числа симметричны.

*   **Диапазон**: Симметричный интервал $[-\frac{3^N-1}{2}, +\frac{3^N-1}{2}]$.
*   **Нормализация**: Ведущие нули строго запрещены в канонической сериализованной форме. Единственное допустимое представление для Нуля — это один нулевой трит `0`.

## 4.2 T81Float и dmath

**Статус: Реализовано (Ядро)**

Арифметика с плавающей запятой является основным источником недетерминизма в кросс-платформенных вычислениях. T81 заменяет аппаратные флоаты IEEE-754 полностью программно-определяемым форматом: **`T81Float`**.

### 4.2.1 Каноническое определение
`T81Float<M, E>` — это кортеж $(s, m, e)$, представляющий значение:
$$
V = s \times m \times 3^{e - \text{bias}}
$$
где:
*   $s \in \{-1, 1\}$ — знак (хранится как трит).
*   $m$ — мантисса, $M$-тритное целое число, нормализованное так, что самый старший трит не равен нулю (если только $V=0$).
*   $e$ — экспонента, $E$-тритное целое число.
*   $\text{bias} = \frac{3^E - 1}{2}$.

**Специальные значения**:
*   **Ноль**: $e = 0, m = 0$.
*   **Бесконечность**: $e = e_{\max}, m = 0$.
*   **NaE (Не Сущность)**: $e = e_{\max}, m \neq 0$. (Эквивалент NaN).

### 4.2.2 Бэкенд dmath
Для гарантии побитово точных результатов на x86, ARM и RISC-V, T81 реализует **`dmath`** (Детерминированная математика).
*   **Арифметика**: `Add`, `Sub`, `Mul`, `Div` реализованы с использованием целочисленной математики на мантиссах, с точными правилами округления (округление до четного), применяемыми программно.
*   **Трансцендентные**: Функции, такие как `sin`, `cos`, `exp`, `log`, вычисляются с использованием **разложений в ряд Тейлора** с фиксированным числом итераций и фиксированной точностью констант. Это устраняет зависимость от `libm` хост-ОС, которая различается между glibc, musl и MSVC.

## 4.3 Тензоры и канонические макеты

**Статус: Реализовано и протестировано**

Тензоры (`T81Tensor`) — это "рабочие лошадки" когнитивных уровней. Для поддержки эффективного выполнения и канонического хэширования они следуют строгому макету.

### 4.3.1 Схема памяти
Тензоры хранятся в порядке **Row-Major** (по строкам, стиль C), а не Column-Major (стиль Fortran).
*   **Форма**: Вектор размерностей $(d_0, d_1, \dots, d_n)$.
*   **Шаг (Stride)**: Вычисляется как $s_i = \prod_{j=i+1}^n d_j$.
*   **Выравнивание**: Данные тензора выровнены по границам 64 байта в сегменте памяти `Tensor` для облегчения SIMD-загрузки (AVX-512 / NEON), где это безопасно.

### 4.3.2 Сериализация (.t81w)
Формат `.t81w` (T81 Weights) — это стандартный контейнер для сохранения тензорных моделей. Он разработан так, чтобы быть **дружественным к mmap** и **каноническим**.

**Бинарная структура (Версия 2)**:
1.  **Магический заголовок**: `0x54383157` ("T81W").
2.  **Версия**: `0x02`.
3.  **Оглавление**: Список кортежей `(Hash, Offset, Length)`, отсортированный по хэшу.
4.  **Данные BLOB**: Непрерывные данные тензоров, выровненные с заполнением до 64 байт.

### 4.3.3 Квантование (T3_K)
T81 поддерживает нативный формат троичного квантования под названием **T3_K**.
*   **Размер блока**: $K$ тритов (обычно 64 или 128).
*   **Представление**: Каждое значение квантуется в $\{-1, 0, 1\}$.
*   **Масштабирование**: Каждый блок имеет масштабный коэффициент (T81Float) для аппроксимации исходной величины.

## 4.4 Правила канонической сериализации

**Статус: Реализовано**

Для обеспечения согласованного хэширования (для `CanonRef`) все данные должны быть нормализованы перед сериализацией. Сериализатор обеспечивает **Биективное Отображение** между абстрактными значениями и последовательностями байтов.

1.  **Целые числа (T81Int)**:
    *   Удалить ведущие нули.
    *   Ноль кодируется как один байт `0x00` (предполагая специфическую кодировку).
2.  **Floats (T81Float)**:
    *   Должны быть нормализованы (максимальный сдвиг влево).
    *   Отрицательный Ноль строго запрещен; должен быть преобразован в Положительный Ноль.
    *   Полезная нагрузка NaE обнуляется (нет различия между "сигнальным" и "тихим" битом).
3.  **Коллекции**:
    *   **Maps/Словари**: Ключи должны быть отсортированы лексикографически по их каноническому двоичному представлению.
    *   **Множества**: Элементы должны быть отсортированы.
4.  **Графы**:
    *   Узлы переиндексируются канонической топологической сортировкой. Если граф имеет циклы, применяется детерминированное правило разрешения ничьих (на основе весов ребер).

> **Верификация**: `tests/cpp/test_property_invariants.cpp` проверяет эти свойства с помощью тестирования на основе свойств (фаззинга), гарантируя, что $Serialize(Deserialize(Serialize(X))) \equiv Serialize(X)$.
