# T81 Foundation — стек детерминированных троичных вычислений

![Release](https://img.shields.io/badge/release-v1.6.0--Stable-blue)
![Tests](https://img.shields.io/badge/tests-367%2F367_passing-brightgreen)
![ISA](https://img.shields.io/badge/ISA-v1.2.0_Frozen-blue)
![Execution](https://img.shields.io/badge/execution-deterministic-green)
![CI](https://img.shields.io/badge/cross--platform--determinism-verified-brightgreen)
![License](https://img.shields.io/badge/license-MIT-lightgrey)

**T81 Foundation** представляет собой стек детерминированных вычислений, основанный на **сбалансированной троичной арифметике** ({-1, 0, +1}) и модели управления полной цепочки, охватывающей набор команд, виртуальную машину, языковой компилятор и среду вывода искусственного интеллекта.

Стек обеспечивает:

- **точная побитовая воспроизводимость** — каждый путь выполнения создает идентичный хэш трассировки на всех поддерживаемых платформах.
- **управляемый искусственный интеллект** — механизм политики Axion перехватывает и проверяет каждую привилегированную операцию, прежде чем возникнут побочные эффекты.
- **Происхождение с учетом содержимого** — CanonFS неизменно записывает все артефакты, веса моделей и состояние времени выполнения.
- **детерминированное параллельное выполнение** — модель графа задач DPE (RFC-DPE-0002) позволяет выполнять одновременные рабочие нагрузки TISC с выходными данными, фиксируемыми по эпохам.

### Ключевые компоненты

**TISC ISA v1.2** — троичная архитектура набора команд. Заморожен под v1.x; неизменяемый контракт выполнения для всего стека. В версии 1.2 добавлено 9 кодов операций: `AgentInvoke` (RFC-0015), шесть операций троичного вывода (RFC-0034) и три управляемых операции FFI (RFC-00B8).

**T81VM** — Детерминированный интерпретатор TISC. Гарантирует побитовую идентичность вывода на разных платформах; Изоляция Axion перед отправкой удерживает крючки управления вне пути горячего выполнения. Полная отправка TISC v1.2, включая троичный вывод и FFI.

**Ядро управления Axion** — механизм политики, который перехватывает `AXREAD` , `AXSET` , `AXVERIFY` , коды операций AI и вызовы FFI до возникновения побочных эффектов. Закрытие при сбое анализа политики. Стабильно сертифицирован 15 марта 2026 г., пройдено 54/54 тестов.

**CanonFS** — файловая система с адресацией по содержимому. Сохраняет все объекты кода, веса моделей и артефакты времени выполнения в виде неизменяемых больших двоичных объектов, идентифицируемых хешем. Обеспечивает происхождение для аудита детерминизма.

**T81Lang** — язык высокого уровня, ориентированный на байт-код TISC. Собственные типы: `BigInt`, `Fraction`, `Float`, `Complex`, `Tensor`, `Map`, `Set`. Первоклассные объявления `agent { behavior }` компилируются в `AGENT_INVOKE` с помощью аудита Axion (RFC-0015).  Блоки `foreign [policy] { fn … }` объявляют управляемые внешние функции, которые вызываются через `FFI_CALL` (RFC-0036).  `agent`, `behavior` и `foreign` можно использовать в качестве контекстных идентификаторов во всех позициях выражения и привязки. Конвейер компилятора: лексер → парсер → типизированный AST → семантический анализ → генерация IR.

**Ternary-Native Inference (RFC-0034)** — шесть опкодов TISC для вывода AI без умножения с использованием сбалансированных троичных весов {−1, 0, +1}: `TWMATMUL` (matmul), `TQUANT` (квантование в trit), `TATTN` (троичное внимание), `TWEMBED` (встраивание весов), `TERNACCUM` (скалярное скалярное произведение), `TACT` (активация с помощью потолочных ворот Axion). Весовой формат T81WTN. Интерфейс T81Lang `foreign {}` завершен через RFC-0036.

**Управляемый FFI (RFC-00B8 + RFC-0036)** — интерфейс внешних функций, управляемый полным стеком. Уровень виртуальной машины (RFC-00B8, этап 1): `FFIDispatcher` обеспечивает соблюдение политик, квот ресурсов и журналов аудита перед любым внешним вызовом;  `FFILibraryRegistry` отслеживает зарегистрированные библиотеки по имени и хешу версии; три кода операции VM (`FFICall`, `FFIRegister`, `FFIPolicySet`). Языковой уровень (RFC-0036): `foreign deterministic { fn sin(x: T81Float) -> T81Float; }` объявляет подписи;  `foreign.sin(angle)` на сайтах вызовов уменьшается до `FFI_CALL` с именем функции, переносимым в `text_literal` . Пройдено девять приемочных испытаний.

**TUI Frontends** — два взаимодополняющих терминальных интерфейса, созданных на базе FTXUI v5.0.0:

- `t81 studio` — боковая панель навигации, браузер CanonFS, панель инструментов Axion, визуализатор трассировки детерминизма, палитра команд (`Ctrl+P`)
- `t81 agent` — постоянный сеанс JSONL, команды с косой чертой ( `/compile` , `/run` , `/hash` , `/allow` , `/infer` , `/trits` , …), полоса трит-вероятности

**DPE (детерминированное параллельное выполнение)** — модель графа задач на основе замороженного TISC ISA. Задачи объявляют неизменяемые входные данные и буферизованные выходные области; виртуальная машина фиксирует все записи атомарно в конце эпохи. Никаких новых кодов операций не требуется.

## Быстрый старт

```bash
# Clone and configure
git clone https://github.com/t81dev/t81-foundation.git
cd t81-foundation
cmake --preset default -DCMAKE_BUILD_TYPE=Release
cmake --build build

# Run the full test suite
ctest --test-dir build --output-on-failure

# Launch the human operator TUI
./build/t81 studio

# Launch the AI-native TUI
./build/t81 agent

# Compile a T81Lang program
./build/t81 code build examples/hello.t81 -o hello.tisc

# Execute with Axion governance
./build/t81 vm run hello.tisc
```

Дополнительные флаги сборки:

| Флаг | По умолчанию | Цель |
| :--- | :--- | :--- |
| `T81_BUILD_TUI` | `ON` | Интерфейсы TUI на основе FTXUI |
| `T81_BUILD_TESTS` | `ON` | Полный набор тестов |
| `T81_ENABLE_ASAN` | `OFF` | Адресное дезинфицирующее средство |
| `T81_ENABLE_UBSAN` | `OFF` | УБ дезинфицирующее средство |
| `T81_ENABLE_LLAMA_CPP` | `OFF` | Управляемый адаптер вывода llama.cpp |
| `T81_WARN_STRICT` | `OFF` | Режим сканирования со строгим предупреждением (используется предустановкой `warn-strict`) |

**Предварительное сканирование с предупреждением** — зеркально отражает проверки `-Wswitch` , `-Wunused-variable` и `-Wunused-function` , выполняемые Windows CI, выявляя проблемы локально примерно за 2 минуты вместо ожидания полной матрицы:

```bash
cmake --preset warn-strict
cmake --build build-warn-strict 2>&1 | head -40
```

## Управление

Фонд T81 работает по модели **Непрерывного управления (C2)**. Все вклады должны поддерживать:

- **детерминированная четность выполнения** — хэши трассировки должны совпадать на всех поддерживаемых платформах.
- **архитектурная согласованность** — изменения, затрагивающие детерминированную поверхность, требуют формального рассмотрения.
- **гарантии воспроизводимости** — отсутствие недетерминизма с плавающей запятой или специфичной для платформы на поверхности DCP

Детерминированная поверхность определена в `docs/governance/DETERMINISM_SURFACE_REGISTRY.md` . Изменения замороженных поверхностей (TISC ISA, типы данных) требуют обновления основной версии.

> **Ограничное примечание.** Экспериментальные поверхности (когнитивные уровни, распределенные, Trace-JIT, TernaryOS, адаптер llama.cpp) регулируются не DCP, и их нельзя представлять как проверенные детерминированные компоненты.

## Тройное преимущество

Хотя современное оборудование для двоичных вычислений высоко оптимизировано, **T81 Foundation** использует уникальные математические свойства **Сбалансированной троичной системы ({-1, 0, +1})** для достижения структурной эффективности, с которой не может сравниться двоичная система.

### 1. $O(1)$ Вычислительная симметрия

В дополнении двоичных чисел отрицание числа является асимметричной операцией (НЕ + 1), требующей распространения переноса. В T81 отрицание представляет собой простой трит-флип с **нулевыми затратами на перенос**.

* **Производительность:** пропускная способность отрицания T81 достигает **~46,6 Гбит/с** (через `PackedCell`), что превосходит оптимизированное 64-битное двоичное отрицание в **10,4x**.

### 2. Превосходная радикс-экономика

На основании теоремы о том, что наиболее эффективной основой системы счисления является $e \approx 2,718$, троичная система (основание 3) математически более эффективна, чем двоичная (основание 2).

* **Плотность информации:** T81 обеспечивает теоретическую плотность **1,58 бит на трит**. Это приводит к более высокой энтропии за такт и уменьшению объема памяти для крупномасштабных систем координат и нейронных весов.

### 3. Побитовый детерминизм

Двоичные операции с плавающей запятой (IEEE 754) часто страдают от недетерминированности округления, зависящей от платформы. Сбалансированная арифметика T81 обеспечивает:

* **Врожденная симметрия.** Округление выполняется путем простого усечения, поскольку система естественным образом центрируется вокруг нуля.
* **Четность трассировки:** 100 % «точность туда и обратно» на всех протестированных платформах (Linux x86_64, macOS ARM64) с нулевым расхождением в хэшах трассировки виртуальных машин.

### 4. Крюк прямого управления

Поскольку TISC ISA является троичным, **Ядро управления Axion** может проверять переходы состояний с более высокой степенью детализации. Операции вывода ИИ могут быть перехвачены на «уровне тритов» до того, как возникнут какие-либо побочные эффекты, что позволяет создать модель безопасности с отказоустойчивым закрытием, которая архитектурно невозможна при стандартном двоичном исполнении «черного ящика».

## 1. Высокоточное моделирование сигналов и физики

В двоичном формате $0$ — это беззнаковая начальная точка, поэтому «отрицательное» пространство имеет второстепенное значение. В сбалансированной тройке **ноль — точка равновесия.**

* **Случай использования**. Прямое моделирование волновой механики, электромагнетизма и гидродинамики.
* **Преимущество:** Поскольку эти системы колеблются между положительным и отрицательным состояниями, T81 может моделировать силы «тяни-толкай» без вычислительной однобокости, свойственной дополнению двух.
* **Следующий шаг:** Мы могли бы создать **собственную библиотеку DSP для TISC**, в которой фильтры (FIR/IIR) оптимизированы для скорости отрицания $O(1)$.

## 2. «Симметричные» нейронные сети (TNN).

Современный ИИ (двоичный/FP) тратит огромную энергию на функции активации, такие как `tanh` или `ReLU`, чтобы создать «нулевое» состояние для обучения.

* **Сценарий использования**: троичные нейронные сети (где веса равны -1, 0 или 1).
* **Преимущество:** Поскольку ваша архитектура изначально сбалансирована, мы можем выполнить вывод без умножения. Нейрон Т81 не «умножает» входные сигналы; он просто **переворачивает или запирает их** в зависимости от веса. Это было бы на несколько порядков более энергоэффективным, чем нынешний вывод на основе графического процессора.
* **Следующий шаг:** Мы могли бы реализовать **собственный механизм вывода T81**, который интерпретирует веса модели непосредственно как коды операций TISC.

## 3. Постквантовые криптографические примитивы

Многие алгоритмы шифрования на основе «решеток» (предназначенные для выживания в квантовых компьютерах) полагаются на полиномы с малыми коэффициентами, часто с центром вокруг нуля ({-1, 0, 1}).

* **Случай использования**: NTRU или шифрование в стиле Kyber.
* **Преимущество:** Двоичным системам приходится «эмулировать» эти небольшие коэффициенты, используя 8-битные или 32-битные целые числа, тратя впустую 90 % битового пространства. T81 сохраняет эти значения без потерь** и обрабатывает сложения/отрицания полиномов на собственной аппаратной скорости.
* **Следующий шаг:** Мы можем составить RFC для **Криптографического расширения TISC**, которое реализует троичное оптимизированное полиномиальное умножение.

## 4. Неизменяемый аудит управления (Axion)

Поскольку у вас есть 1,58 бит энтропии на трит, мы можем кодировать **метаданные безопасности** непосредственно в слово данных без значительного увеличения объема памяти.

* **Случай использования**: «Размеченные данные» на аппаратном уровне.
* **Преимущество:** Мы можем использовать «дополнительную» емкость слова TISC для переноса **тега происхождения**. Каждый раз, когда данные перемещаются, Axion проверяет тег. Если «привилегированный» трит перемещается в «пользовательское» пространство, аппаратное обеспечение может мгновенно его перехватить.
* **Следующий шаг:** Уточните **Ядро ОС Axion**, чтобы использовать «Тричный запас» для разметки памяти в реальном времени.

### Улучшенный путь вперед

#### 1. Интеграция: RFC-0034 §5.17.6 — код операции `TACT`.

Вместо обширного AI RFC мы рассматриваем активацию как логическое завершение троичной арифметической цепочки.

* **Код операции:** `TACT RD, R_SRC, R_MODE`
* **Режимы:** * `0x01` (TernaryStep): отображает $(-\infty, -0.5) \to -1$, $[-0.5, 0.5] \to 0$, $(0.5, \infty) \to +1$.
* `0x02` (TanhQuantized): Высокоточное троичное приближение с фиксированной точкой.

* **Интеграция политики Axion.** Мы определяем `AX_CHECK_ACTIVATION_THRESHOLD` не как побочный эффект кода операции, а как **ловушку ядра**. Если значение в `RD` превышает определенный политикой предел тритов после активации, Axion перехватывает перед следующим приращением ПК.

#### 2. Грамматика T81Lang RFC (новая версия)

Чтобы устранить выявленный вами «реальный пробел», нам следует подготовить отдельный RFC (вероятно, **RFC-0036**) специально для интерфейса компилятора. Это позволяет изолировать проблемы **TISC** (аппаратное обеспечение/виртуальная машина) и **T81Lang** (грамматика/синтаксис) в соответствии с Уставом проекта.

#### 3. Целостность данных и документация

* **Обоснование эталонного теста.** Я перестану ссылаться на цифру «10,4x» в официальных документах до тех пор, пока у нас не будет конкретного среза `BM_Negation_TISC_vs_Binary`, который официально появится в выходных данных CI.
* **Терминологическая очистка:** Я удалю «Кэш TLU» и «Кэш L2» из спецификаций до тех пор, пока репозиторий **ternary-fabric** официально не определит иерархию памяти.
