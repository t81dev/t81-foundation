## 4. Dynamic checks on HIGH findings

### 4a. JIT vs interpreter divergence (A-H1) — EXECUTED, CONFIRMED

Probe: `~/workspace/t81-audit/jit_overflow_probe.cpp` (mirrors
`tests/cpp/jit_trace_equivalence_test.cpp`: `Insn` tuples, `make_interpreter_vm`,
`run_to_halt`, register/tag readback from `vm->state()`).
Program: r1 = INT64_MAX−5; r2 = 1; r3 = N; loop: `Add r1,r1,r2; Dec r3;
JumpIfNotZero loop,r3; Halt`. Control N=10 (never hot → interpreter-only).
Experiment N=60 (crosses the hot threshold 50 → trace engages).
Compiled against the built libs in `build-full` (flags and link line copied
from the `t81_vm_print_test` target); exit 0 for both compile and link.
Verbatim output:

```
=== iters=10 ===
halted=1 r1_value=5 r1_tag=BigIntHandle
jit_trace_enter=0 jit_trace_exit=0
=== iters=60 ===
halted=1 r1_value=55 r1_tag=Int
jit_trace_enter=1 jit_trace_exit=1
expected_big_10=9223372036854775812 expected_big_60=9223372036854775862
wrapped_60=-9223372036854775754
```

Interpretation (executed evidence, not static inference): the control run is
interpreter-correct (BigIntHandle tag, JIT never engaged). The hot run engaged
the trace (enter=1, exit=1) and produced tag Int with value **55** — not even
the wrapped value, but handle arithmetic: at trace start the accumulator
already held a BigIntHandle (iterations 6–49 produced BigInts; iteration 49's
result handle 44), the trace computed 44+1=45 and tagged it Int, then 10 more
trace iterations added 1 each → 45+10=**55**, exactly matching the observed
value. This confirms the audit's finding precisely, including its
"BigIntHandle operand gets its handle added and tagged Int" clause.
Correct value would have been 9223372036854775862; observed 55 is pure garbage.
**A-H1: dynamically CONFIRMED** (upgraded from static to executed evidence).

normally — the loop requirement was satisfied from load time onward.
**B-H2: dynamically CONFIRMED end-to-end** (upgraded from static to executed
evidence).
