# Глава 8: Верификация и аудит

## 8.1 Методология формальной верификации

**Статус: Реализовано**

T81 применяет стратегию многоуровневой верификации, переходя от модульных тестов к формальной проверке свойств.

### 8.1.1 Стек верификации

1.  **Модульные тесты (L1)**: Проверяют отдельные функции и классы.
    *   Пример: `tests/cpp/test_T81Int.cpp` проверяет `T81Int::add(1, 1) == 1T`.
2.  **Тестирование на основе свойств (L2)**: Генерирует случайные входные данные для проверки инвариантов (стиль QuickCheck).
    *   Пример: `tests/cpp/test_property_invariants.cpp` проверяет $\forall a, b: a + b = b + a$.
3.  **Фаззинг-тестирование (L3)**: Подает некорректные входные данные в парсер и VM для обеспечения устойчивости к сбоям.
    *   Пример: `tests/cpp/frontend_fuzz_test.cpp` использует `libFuzzer`.
4.  **Интеграционные тесты (L4)**: Запускают полные сквозные программы и проверяют вывод.
    *   Пример: `tests/cpp/e2e_arithmetic_test.cpp`.
5.  **Гейты детерминизма (L5)**: Проверяют побитовую воспроизводимость в разных средах.

## 8.3 Тестирование на основе свойств

**Статус: Реализовано**

Мы используем **Тестирование на основе свойств** (Property-Based Testing), чтобы доказать, что алгебраические законы выполняются для наших пользовательских числовых типов.

### 8.3.1 Аксиомы кольца
Файл `tests/cpp/test_property_invariants.cpp` программно проверяет, что `T81Int` и `T81Float` удовлетворяют аксиомам Кольца:
1.  **Ассоциативность**: $(a + b) + c = a + (b + c)$
2.  **Коммутативность**: $a + b = b + a$
3.  **Тождество**: $a + 0 = a$
4.  **Обратный элемент**: $a + (-a) = 0$
5.  **Дистрибутивность**: $a \times (b + c) = (a \times b) + (a \times c)$

Эти тесты выполняют миллионы итераций со случайными входными данными (включая граничные случаи, такие как `MaxInt`, `MinInt`, `Zero`), чтобы обеспечить высокую статистическую уверенность в корректности.

## 8.4 Гейт детерминизма

**Статус: Активно**

**Гейт детерминизма** (`scripts/ci/t81lang_repro_gate.py`) — это последняя проверка перед слиянием любого кода.

### 8.4.1 Механика
1.  **Согласованность компиляции**: Компилирует набор из 5+ канонических тестовых программ (`*.t81`) дважды. Сравнивает бинарный вывод Прохода А и Прохода Б. Любое битовое различие вызывает немедленный сбой.
2.  **Агрегированное хэширование**: Вычисляет хэш SHA-256 сгенерированного байткода для всех тестов.
3.  **Верификация базовой линии**: Этот агрегированный хэш сравнивается с зарегистрированным "Золотым Хэшем". Если логика компилятора изменяется (что приводит к другому байткоду), хэш сместится, и сборка завершится неудачей. Это гарантирует, что изменения компилятора являются преднамеренными и проверенными.

### 8.4.2 Прослеживаемость
Когда гейт проходит, он выводит:
```text
[PASS] T81Lang gates passed: fixtures=5 hash=a7f92b...
```
Этот хэш записывается в логи CI, предоставляя неизменяемую запись состояния компилятора для данного релиза.
