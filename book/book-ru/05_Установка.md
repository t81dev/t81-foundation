# Глава 5: Установка и верификация сборки

## 5.1 Требования

**Статус: Стандартизировано**

Сборка T81 требует современного инструментария C++, способного поддерживать функции C++23. Проект требует строгих предупреждений компилятора и соответствия стандартам для минимизации неопределенного поведения.

### Поддерживаемые платформы
*   **Linux**: x86_64, ARM64 (aarch64), RISC-V (rv64gc)
*   **macOS**: Apple Silicon (M1/M2/M3), Intel (устаревшие)
*   **Windows**: Рекомендуется WSL2 (поддержка MSVC экспериментальная)

### Требования к инструментарию
*   **Компилятор**:
    *   Clang 18+ (Рекомендуется из-за строгости)
    *   GCC 14+
    *   MSVC 19.38+ (VS 2022)
*   **Система сборки**: CMake 3.25 или новее.
*   **Python**: Python 3.10+ (Используется для скриптов валидации и привязок).
*   **Ninja**: Рекомендуется для более быстрой сборки.

## 5.2 Сборка из исходного кода

**Статус: Автоматизировано**

Стандартный процесс сборки инкапсулирован в команде `make cmake-ritual`, но может быть выполнен вручную через CMake.

### 5.2.1 Рабочий процесс CMake

```bash
# 1. Клонирование репозитория
git clone https://github.com/t81-foundation/t81.git
cd t81

# 2. Конфигурация (Рекомендуется режим Release для производительности)
cmake -B build -G Ninja \
    -DCMAKE_BUILD_TYPE=Release \
    -DT81_USE_CXX23=ON \
    -DT81_BUILD_TESTS=ON

# 3. Сборка основного исполняемого файла
cmake --build build --target t81
```

### 5.2.2 Опции сборки
Следующие опции CMake управляют конфигурацией сборки:

| Опция | По умолчанию | Описание |
| :--- | :--- | :--- |
| `T81_USE_CXX23` | `ON` | Включить функции C++23 (напр., `std::expected`, `std::print`). |
| `T81_BUILD_TESTS` | `ON` | Компилировать набор верификации (`t81_*_test`). |
| `T81_BUILD_EXAMPLES` | `ON` | Компилировать демонстрационные программы в `examples/`. |
| `T81_ENABLE_ASAN` | `OFF` | Включить AddressSanitizer (Только отладка). |
| `T81_ENABLE_UBSAN` | `OFF` | Включить UndefinedBehaviorSanitizer. |

> **Примечание о детерминизме**: Чтобы гарантировать строгий детерминизм (отключение использования FPU хоста для трансцендентных функций), определите `T81_DETERMINISTIC` вручную, если это не задано по умолчанию:
> `cmake -B build -DCMAKE_CXX_FLAGS="-DT81_DETERMINISTIC"`

## 5.3 Верификация сборки

**Статус: Критично**

После сборки вы **должны** проверить, что созданный бинарный файл соответствует спецификации T81. Успешная компиляция не гарантирует правильного выполнения.

### 5.3.1 Запуск модульных тестов
Запустите стандартный набор тестов через `ctest`. Это выполнит сотни тестов на основе свойств.

```bash
cd build
ctest --output-on-failure
```

### 5.3.2 Гейт детерминизма
Наиболее важной проверкой является **Гейт детерминизма** (Determinism Gate). Этот скрипт компилирует каноническую эталонную программу, запускает ее и сравнивает полученный хэш Трассы Axion с известным хорошим значением.

```bash
# Запустить гейт воспроизводимости
python3 scripts/ci/t81lang_repro_gate.py --binary ./build/t81
```

**Ожидаемый вывод**:
```text
[PASS] Trace Hash: canon:sha3:a7f92b... MATCHES expected baseline.
[PASS] Cycles: 10420 (Exact match)
[PASS] Determinism verification successful.
```

Если этот скрипт не проходит, сборка считается **запятнанной** (tainted) и не должна использоваться для производственных или аудиторских задач.

### 5.3.3 Верификация целей архитектуры
Убедитесь, что граф сборки соответствует архитектурной спецификации:

```bash
python3 scripts/ci/check_architecture_targets.py
```

## 5.4 Устранение неполадок

*   **"C++23 not supported"**: Обновите ваш компилятор. T81 сильно зависит от современных функций C++ для безопасности типов.
*   **"Trace Hash Mismatch"**: Возможно, вы линкуетесь с другой версией стандартных библиотек, или сработал фоллбэк `dmath`. Убедитесь, что `T81_DETERMINISTIC` определен.
*   **"SIMD Instruction Fault"**: T81 пытается обнаружить наличие AVX2/NEON. Если вы выполняете кросс-компиляцию, убедитесь, что флаги цели правильные.
