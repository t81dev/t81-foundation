## Proposed replacement Section 10 — M2 and M3

This section is a **prospective methodological amendment**, not an assertion that #635 prescribed paired inference or that #637's tests approve it. It replaces the original statistical procedure only after activation. It deliberately differs from #637 by removing minimum-effect failure as an automatic NOT SUPPORTED rule, adding instruction-regression testing, and controlling regression multiplicity/fastest-baseline selection.

### Analysis unit, estimands and design justification

For each pattern, collect exactly ten complete blocks, each containing candidate plus all four baselines on the same precomputed corpus, core, executable configuration and declared environment. Preserve block/run identifiers and actual order in authenticated evidence. Retain the existing planned rotation `mode=(j+r) mod 5` for blocks r=0..9 and positions j=0..4; every mode occupies every position twice. Pairing is fixed before collection, not reconstructed by sorting results. The measured unit is the block-level metric total, not each of the 10 million decisions; do not pseudoreplicate.

Paired inference is preferred because the block is a planned shared-condition unit and the estimand is a within-block contrast. An identical corpus alone does not establish statistical pairing or independent errors. Pair validity requires the metadata/design conditions above. Rotation balances position frequency, but cannot prove absence of carryover, nonlinear thermal drift or autocorrelation. The working Student-t model assumes independent block differences with an adequately approximated normal mean-error model; ten blocks provide weak diagnostics. Report these limits and all diagnostics, without selecting Welch/paired tests or excluding blocks after inspecting outcomes. Invalid/missing block identities are BLOCKED; no alternative analysis is silently substituted. The statistical basis is [NIST paired observations](https://www.itl.nist.gov/div898/handbook/prc/section3/prc311.htm); unequal-variance unpaired Welch analysis has a different sampling model and [Satterthwaite degrees of freedom](https://itl.nist.gov/div898/handbook/eda/section3/eda353.htm).

For comparison, the original unpaired Welch model uses `nu=(s_c^2/10+s_b^2/10)^2 / ((s_c^2/10)^2/9+(s_b^2/10)^2/9)`, generally not 9; a degenerate zero denominator was not specified in #635. It is not interchangeable with the variance of matched differences.

The sole benefit endpoint is instruction reduction versus Baseline 1 for each pattern: `d=1−mean(Ic)/mean(I1)`. Other instruction comparisons against Baselines 2–4 remain required descriptive controls, not additional opportunities to declare success. All raw I/B/T values for all implementations are reported. Latency is the original steady-clock elapsed duration; it is not claimed to be a CPU-time clock. CPU resource accounting is separately defined in M4. This preserves the research scope and the numerical targets in original Section 1, while resolving the contradictory composite inference wording. [Original #635:285–290](https://github.com/t81dev/t81-foundation/blob/b37005ceda6a3f4349ec9027b2a9be84ea176aa9/docs/research/TERNARY_ADVANTAGE_CANDIDATES.md#L285-L290) [Original #635:467–509](https://github.com/t81dev/t81-foundation/blob/b37005ceda6a3f4349ec9027b2a9be84ea176aa9/docs/research/TERNARY_ADVANTAGE_CANDIDATES.md#L467-L509)

### Estimates, intervals and tests

Report means, sample standard deviations with denominator 9, two-sided 95% Student-t intervals, and every paired candidate-minus-baseline contrast with its 95% interval, separately for each metric/baseline/pattern. For a paired vector D, `t=mean(D)/(s(D)/sqrt(10))`, df=9; the primary instruction p-value is two-sided. Retain the strict p<.01 numerical threshold. Require a favorable point direction as well as significance. The 95% critical value is `t(9,.975)`≈2.2621571628540993, replacing #635's normal 1.96 explicitly.

Qualify the 15% target with a nominal one-sided 99% lower bootstrap bound L for d, using 10,000 paired resamples of whole blocks. Each draw is bounded(10) under E1/E2; use the same sampled block indices for candidate and baseline, preserving the ratio-of-means estimand. Sort reductions and use inverse empirical-CDF ranks 100 and 9900 (zero-based indices 99,9899) for L and U. Reset the bootstrap stream per pattern, independently of the corpus stream. Require L≥.15 as well as d≥.15 and primary p<.01. This minimum-effect qualification is new relative to #635 and is not an exact coverage guarantee at n=10; U is reported for evidence, not an automatic NOT SUPPORTED trigger. Use the mandatory exact rational ordering and 3/20 decision comparisons specified in B2 below; never introduce an epsilon acceptance allowance.

Branch/latency success checks are **descriptive**: mean(Bc)≤mean(B1) and mean(Tc)≤min_b mean(Tb), b=1..4. Choose the fastest observed baseline separately per pattern, with a lowest-baseline-number tie break. Equality does not require a significant difference, and these checks do not prove equivalence or statistical non-inferiority. No non-inferiority margin is invented.

For demonstrated regressions, predeclare **18 contrasts across the full experiment**: for each of three patterns, Ic−I1, Bc−B1, and Tc−Tb for each b=1..4 (six per pattern). For each contrast use a two-sided simultaneous Student-t interval:

`mean(D) ± t(9, 1−.01/(2*18)) * s(D)/sqrt(10)`.

A regression is demonstrated only when its lower endpoint is strictly positive. The critical value is approximately **5.211371786975027**, but its quantile definition governs. Equivalently, a positive observed contrast must have two-sided p<.01/18; use strict comparisons at the boundary. This is a new prospective multiplicity rule, with individual confidence 1−.01/18 and nominal joint coverage at least .99 under the marginal model. [Bonferroni's inequality](https://itl.nist.gov/div898/handbook/prc/section4/prc473.htm) does not require independence between contrasts. Testing all four latency contrasts avoids choosing a single unadjusted test after selecting the fastest baseline. A positive contrast against any binary baseline is the operational latency-regression criterion; it resolves the old “all baselines” prose versus “fastest” formula conflict in favor of the latter meaning.

Primary benefit tests remain per-pattern at .01. The global claim requires *all* three patterns to qualify, not any one of three opportunities. Do not claim simultaneous .99 confidence for all individual support results: bootstrap coverage is approximate and individual reports are not familywise adjusted. The regression family is separately controlled because any one regression can veto the overall result. Do not mix its 18 tests with exploratory comparisons or claim broad discovery significance.

### Degenerate observations

Require ten valid paired observations before any calculation. Raw instructions are positive uint64 totals, misses nonnegative uint64, and elapsed_ns positive signed-int64 durations. Zero misses and zero sample variance are valid; zero instruction/latency totals are invalid for this fixed workload. A zero or invalid baseline-instruction denominator blocks analysis.

For an exact paired difference vector with s=0: if its mean is zero, define p=1 and interval [0,0]; otherwise use the deterministic limiting statistic t=±infinity, p=0 and the point interval at that mean, carrying a `DEGENERATE_CONSTANT_DIFFERENCE` flag. Bootstrap constant reductions have point bounds. These are explicit computational/model-limit conventions, not independently calibrated confidence statements for an unknown noisy population. They allow identical deterministic instruction counts to be analyzed without requiring artificial measurement noise. Equal constants do not prove equivalence. Tiny positive variance is not silently rounded to zero; preserve raw integers and stable/exact sums. Missing, nonfinite, fractional raw counters, overflow and contradictory completion evidence are BLOCKED, not degenerate valid observations.

| 2 | NOT SUPPORTED | V and G | Report each demonstrated instruction, branch-miss or latency regression with its contrast, simultaneous interval and adjusted decision. A nonsignificant benefit metric cannot mask it. |
| 3 | SUPPORTED | V and not G and Q | Report d, bootstrap L/U, primary p, means and fastest baseline. This is a bounded software result only. |
| 4 | INCONCLUSIVE | V and not G and not Q | Report which qualification failed; retain positive direction, uncertainty, and evidence below the target separately. |

Thus positive significant gains below 15%, d=0, nonsignificant effects, failure to establish L≥.15, and noisy mean regressions without demonstrated G remain INCONCLUSIVE unless another demonstrated regression vetoes. These are not automatically NOT SUPPORTED. A measured instruction/miss/latency regression that *does* establish G is NOT SUPPORTED even when instruction benefit is nonsignificant.

Separately report `minimum_effect_status`: `ESTABLISHED` if L≥.15; `BOUND_BELOW_TARGET` if U<.15; otherwise `UNRESOLVED`, along with d and its direction. `BOUND_BELOW_TARGET` is explicit evidence against the 15% target, even when the four-outcome label is INCONCLUSIVE. This deliberately preserves #635's small-positive outcome semantics: NOT SUPPORTED is reserved here for demonstrated regressions and is not the logical complement of the entire success hypothesis. Do not describe a confidently sub-target effect as statistically unresolved merely because the composite label is INCONCLUSIVE.

No pooling across patterns. Report all three pattern states, including blocked reasons and retained raw diagnostics. Overall precedence is **BLOCKED > NOT SUPPORTED > INCONCLUSIVE > SUPPORTED**; SUPPORTED requires all three SUPPORTED. A global failure (budget overrun, invalid overall completion, tampering, compiler/executable failure) makes all affected results BLOCKED even if every CSV row exists. A localized missing-pattern record under authenticated, normally exited terminal evidence blocks that pattern and overall; untainted completed patterns may retain their independently valid states. This exception cannot override any nonzero exit, signal, global budget failure, tampering, missing authentication or ambiguous scope. Do not recompute the regression divisor from whichever patterns happen to finish: family size remains 18. Aggregation is a descriptive decision convention, not evidence that all endpoints or native hardware hypotheses were statistically tested.

## Measurement-integrity requirements — M4

The acceptance IDs R01–R11 and exact tests are in `IMPLEMENTATION_REPAIR_PLAN.md`; these requirements are part of the proposed governing r1 contract, not optional documentation.

Collector is single-process with no child workers; no hidden separate memory budget. Equality is allowed, any observed greater peak blocks. A supervisor captures the kernel peak at exit so a transient overrun cannot vanish between polls. Stronger limits, if used, are separately declared and never renamed as this RSS rule.

Supervisor final resource usage is authoritative; record its resolution. Compilation, analyzer and external supervisor resource use are excluded and separately logged; they must not execute concurrently on the dedicated measurement core.

- Bind original and amendment digests, approval id, run id, source commit, executable/toolchain/flags/assembly hashes, all full corpus hashes, N/R, block/order identifiers, PMU configuration/read scheduling status, environment/control evidence, exact row coverage, CSV/stderr hashes, exit/signal, CPU/RSS peak and explicit global/per-pattern failure scope. ### Experiment-local trusted-runner profile — draft 0.2 clarification of M4

**Scope and status.** This specifies one short-lived, local supervisor/verifier workflow for this experiment. It is not a daemon, new T81 governance surface, or repository-wide signing framework. No approval identity, key, trust anchor, runner account or measurement host has been provisioned in this packet. All concrete credentials remain **UNCONFIGURED**. Cryptographic policy here is proposed; mathematical bootstrap verification above is executed evidence.

**T1 — provisioning and key custody.** A named maintainer provisions a dedicated trusted Linux measurement host, installs/reviews the supervisor and verifier, and designates its operator. The maintainer holds a separate approval Ed25519 private key offline or in a protected signing facility. The operator provisions a distinct runner Ed25519 key, outside the repository and collector sandbox, readable only by the trusted supervisor account. The recommended minimal launch is a manually invoked privileged, short-lived supervisor which forks a collector under a different restricted, nonprivileged OS UID and drops all collector capabilities. The collector may not read the runner private key, modify approval/trust/eligibility files or the output directory, or trace the supervisor. It inherits only approved stdin and stdout/stderr pipes, no signing sockets, keys, secret environment variables or extra descriptors. A same-UID collector with read access to the signing key is explicitly **not** this trust model. No key-generation, credential installation, privilege changes or real signing occurs during this review.

**T2 — trust bootstrap and separation of roles.** The verifier is configured with the maintainer's exact raw 32-byte Ed25519 public key and its SHA-256 fingerprint through an authenticated out-of-band handoff (in-person/known authenticated channel) from that named maintainer. The recipient checks the fingerprint and pins both bytes and identity in a protected experiment-local trust file *before* any run. Never trust a key supplied by a run manifest, a self-signed runner record, or an unauthenticated repository download. The maintainer signs a runner delegation naming the runner public key/fingerprint, operator/host, production role, experiment/revision, approved packet digest, campaign id, validity window and allowed run scope. The runner cannot sign its own maintainer approval. Revocation/replacement is an explicit signed maintainer update pinned by the verifier; no network trust-discovery or global registry is required. A compromised root/supervisor/host/kernel or malicious authorized operator is outside the scientific trust guarantee and must be disclosed; signatures attest capture and custody, not truth of PMU readings or scientific correctness.

**T3 — exact approval representation.** `FINAL_APPROVAL_RECORD.md` is an unsigned review candidate, not an activation credential. Formal approval is a separate immutable `approval.json` payload plus detached Ed25519 signature by the pinned maintainer key. Required fields: record_type=`maintainer_approval`, schema_version=1, decision=`APPROVE`, approver identity/key fingerprint, UTC timestamp, original commit/blob/SHA-256, proposed identifier `EXP-T81-COMP3-01/r1`, amendment identifier/draft version/digest, exact SHA-256 digests of all five final approval documents, and explicit booleans M1=M2=M3=M4=true. Also bind a fresh campaign id, permitted host and GCC/Clang configurations, runner-delegation digest, full-run retry/attempt policy, and whether measurement execution is separately authorized. The latter defaults to false; review approval never implicitly authorizes collection. Missing, pending, false, mismatched or untrusted fields fail closed. Any edit to the approval packet requires a new maintainer decision and signed payload; do not fill blanks in the immutable review packet and assume its previous hash still applies.

**Signed bytes.** Use an experiment-local canonical JSON subset: ASCII keys sorted recursively, UTF-8 with `ensure_ascii=true`, separators `(',',':')`, no indentation, duplicate keys or floating-point JSON numbers, and exactly one trailing LF; integers are base-10, strings escape per JSON, arrays retain declared order. Noncanonical encodings are rejected, not reinterpreted. Sign the exact concatenation `ASCII("T81-COMP3-r1/<TYPE>/v1") + NUL + canonical_payload_bytes`, with TYPE fixed to APPROVAL, DELEGATION, ELIGIBILITY or RUN by the verifier's expected record role. Detached signature bytes are base64 in a separate envelope; the envelope key id is only a lookup into already trusted keys, never a trust source. Public-key fingerprints hash the raw 32 bytes. Artifact SHA-256 values bind exact file bytes, not decoded/normalized equivalents. This closes cross-record substitution and ambiguous JSON signing without introducing a general signing framework. Exact encoders and Ed25519 verification require post-approval tests; no real signatures have been produced here.

**T4 — eligibility and launch binding.** After implementation repairs and actual Linux validation, the maintainer signs an eligibility payload naming the approved packet/approval/delegation digests, repaired source commit and a sorted source-file hash manifest, compiler/link flags and versions, approved executable hashes, dependency/runtime image identity, full corpus hashes, assembly/evidence hashes, and allowed environment profile. No dependency on a future floating branch HEAD is allowed. Supervisor and verifier check this chain before launch. The source/executable/corpus snapshot is owned by the trusted operator and immutable to the collector; the supervisor hashes the exact executable file object it will execute (same descriptor/inode, e.g. Linux descriptor-based execution), not a mutable path that can be swapped after hashing. Control dependency files and execution environment under the declared host profile; bind pre/post environment evidence and document remaining noise. Corpus files are read-only to the collector, or independently regenerated/verified by the trusted supervisor before a signed run record is issued; a collector assertion of its own corpus hash is insufficient. The operator must accept the actual intended-host source and hash evidence, not merely the original uncorrected #637 executable.

**T5 — run id and replay protection.** Supervisor allocates a fresh 128-bit OS-CSPRNG nonce rendered as 32 lowercase hex characters, plus the preapproved campaign id and monotonically increasing attempt number. Before launching, it reserves that tuple under a filesystem lock in an operator-owned experiment-local append-only journal inaccessible to the collector. Never reuse a RESERVED, completed, failed or abandoned identifier. It records every attempt and enforces the signed campaign's host/compiler scope, maximum attempts and whole-run retry policy. A retry after an independently established infrastructure failure gets a new id and retains the failure record; no mode-level cherry-picking or row splicing is permitted. A successful unfavorable result is not grounds for an unapproved replacement run. Missing retry limits or unclear campaign scope block launch; they are human configuration, not inferred from data.

A read-only audit verification may be repeated idempotently for the same artifact. Admission as a new experiment observation is separate: the verifier checks the protected admission journal and rejects duplicate run ids or reused signed evidence as new data. Thus replay protection does not forbid reviewing the same report twice. No persistent service is required; the two protected per-campaign journals are ordinary local files. Restoring an old journal/trust snapshot is outside the trusted-host assumption and must not be used to regain admission eligibility.

**T6 — supervisor-observed termination and budgets.** The supervisor launches the one approved single-process collector, owns the capture pipes/output files and waits for that exact child using Linux `wait4` or an equivalent native integer-resource interface. Decode the raw wait status using WIFEXITED/WEXITSTATUS and WIFSIGNALED/WTERMSIG; store the raw status, exit code or terminating signal, and never convert a signal into exit 0. Record kernel rusage user/system seconds and microseconds as integers; CPU total is their exact sum in microseconds. Record native ru_maxrss, documented Linux KiB units, and exact bytes=ru_maxrss*1024. Do not truncate floating-point seconds to decide a one-microsecond boundary. A signal, exit≠0 or inability to obtain trustworthy resource status is a global BLOCKED result regardless of CSV completeness. Enforce the approved single-process/no-worker launch profile so child work cannot escape CPU/RSS accounting; any violation invalidates the run. The precise launch restrictions are verified on the intended Linux host, not asserted by this paper design.

After child termination and final resource checks, finish draining and closing stdout/stderr captures, hash their complete bytes, and write one canonical terminal manifest atomically (temporary file plus rename) before signing/admission. Final measurements and budget accounting include the collector's output/exit path. Supervisor failure or crash before an authenticated terminal record leaves no valid completion; a partial file or bare CSV is not evidence of success. A failed run may have an authenticated failure manifest, but that manifest is never admitted as successful evidence. No signing key is ever handed to the collector.

**T7 — bound terminal manifest and decision order.** RUN binds its role/schema, artifact_kind=`measurement`, run/campaign/attempt ids, approved protocol/original/packet/approval/delegation/eligibility digests, source tree/executable/dependency/corpus/assembly hashes, full CSV and stderr hashes, N=10000000/R=10, all 150 `(pattern,mode,block_id)` records and actual run order, pre/post environment/profile evidence, exact PMU configuration/read status, supervisor-observed start/exit times and raw terminal status, exact CPU/RSS, and explicit global/pattern failure reasons. The operator's trusted signer produces these fields from captured/verified evidence; it must not blindly sign arbitrary collector-provided JSON. Signature authenticity does not excuse mismatched rows, invalid integer fields, false resource claims or failed oracle/payload checks.

The verifier first checks pinned keys and role/delegation, signed M1–M4 approval, packet and eligibility digests, campaign scope/timing/nonce, signature and exact artifact hashes; it then checks terminal/resource/global status, raw integer domains and matched coverage/controls before applying any statistical predicates. Nonzero exit, signal, over-budget final accounting, tampering, unauthenticated evidence or unknown failure scope block globally. Authenticated normal-exit evidence with independently identified pattern-local missing/invalid observations may retain unaffected complete-pattern diagnostics/states under the existing table, but the incomplete pattern and overall experiment remain BLOCKED; this exception never rescues a failed collector. A valid signature alone is not a `success=true` shortcut. All failure evidence is retained.

**T8 — tests cannot masquerade as measurements.** Test keys have a separate test trust store and explicit delegation role `test`, payload artifact_kind=`synthetic`, and an audit-only verifier that emits diagnostic results only. The measurement verifier has no `allow_test_key` override and accepts only production runner delegations, measurement kind, valid measurement authorization and the signed campaign scope. Changing a test payload's kind invalidates its signature; signing `measurement` with a test key still fails role/trust checks. A production supervisor derives kind from its approved invocation, not collector input, and must not sign synthetic counterexamples as measurement artifacts. Review mathematics here uses no real or test credentials. The current proposed hashes are content identities, not authenticated measurement attestations.

**Outstanding human decisions — explicit, not assumed.** Name the maintainer/approval-key custodian and authenticate/pin the real approval public key; name the operator, host, restricted collector identity and protected storage, provision/delegate the real runner key with exclusive custody; select the intended compiler/host profile and bounded campaign/retry scope; then sign formal M1–M4 approval and, only after actual repairs/validation, eligibility and any separate measurement authorization. None is configured by this finalization. These are the only remaining configuration choices; the statistical rules, frozen bootstrap sequence and acceptance thresholds are not reopened.
