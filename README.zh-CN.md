## 什么是 T81？

**T81 基金会是一个已实现的实验性计算架构与开源科学研究项目，旨在探讨替代计算表示法（特别是平衡三进制）是否能比传统二进制系统提供可测量的优势。**

T81 是一个**已实现且能正常运行的架构**：它将三进制指令集计算机（TISC）定义为其计算指令契约，并通过托管虚拟机（T81VM）和裸机独立微内核环境（AArch64 QEMU 上的 Axion OS / TernaryOS）展示了有边界的跨环境执行。

该项目从多个层面研究计算：数学表示、算法、软件执行、存储、硬件架构以及可验证的系统行为。其以研究为先的架构起源于离散数学、CWEB/Hanoi 以及对替代数字系统的研究，之后扩展到语言、虚拟机、指令、策略和研究保障子系统。

第二个明确的实验方向是**表示感知型自适应执行**：为特定工作负载（尤其是 AI/ML）选择数据表示法、算法和执行路径，同时衡量选择、转换、计算和准确性的全部成本。这是一种架构假设，**并非**既定的 T81 性能优势。

其核心问题是：

> 在什么条件下，三进制计算能够优于、简化或以其他方式改进同等的二进制方法？

答案并非不证自明。

一些实验已经证明了有用的数学和表示属性。另一些则表明传统的二进制实现仍然更快或更高效。有几个重要问题仍未得到解决。

T81 的存在就是为了系统地研究这些边界。

**这是一个研究平台，而不是声称已经构建出了性能更优的三进制计算机。**

## 为什么选择三进制？

现代计算绝大多数使用二进制状态：0 和 1。

三进制计算使用三个状态。在平衡三进制中，它们表示为：

$$T = \{-1,0,+1\}$$

这为带符号算术、数值表示、状态编码、决策系统和计算架构创造了有趣的可能性。

例如：

| 属性 | 数学关系 |
| --- | --- |
| 一个三进制位 (trit) | 三种可能的状态 |
| 四个三进制位 | $3^4 = 81$ 种状态 |
| 六个三进制位 | $3^6 = 729$ 种状态 |
| 每个三进制位的信息量 | $\log_2 3 \approx 1.585$ 比特 |
| 81 进制数位 | 四个组合的三进制位 |

这些关系是数学事实。

它们**并不**能证明三进制处理器更快、三进制存储器物理密度更高，或者三进制算法消耗更少的能量。

这些是需要进行适当比较的独立工程问题。

T81 正是在研究这种区别。

## 我们学到了什么？

当研究能够同时识别出机遇与局限性时，它才是有价值的。

**核心结果——不理想的优化二进制比较：** 在下方历史性的 AVX2 矩阵向量实验中，原生 INT8 达到了 **17.15 GFLOP/s**，而打包的 2 位三进制为 **12.91 GFLOP/s**（原生 INT8 实现的吞吐量大约**高出 32.8%**）。这是一个特定于工作负载的结果，并非普遍的基数排名；T81 显著地将其公开发布，因为不利的结果也是证据，而不是需要掩盖的缺陷。

T81 的实验历史产生了几项重要发现。

### 1. AVX2 负面结果：表示密度不等于执行速度

打包的三进制数据可以减少存储需求。

然而，软件仍然必须在传统的二进制硬件上解码、操纵和执行这些表示。

在一次历史性的 AVX2 矩阵向量实验中：

| 实现方式 | 报告的吞吐量 |
| --- | --- |
| 原生 INT8 AVX2 | 17.15 GFLOP/s |
| 打包 2 位三进制 AVX2 | 12.91 GFLOP/s |

紧凑的三进制表示在该工作负载中的表现并没有优于传统的 INT8 实现。

这是一个有边界的实验结果——并不是三进制计算普遍较慢的证明。

[探索打包三进制研究](https://www.google.com/search?q=docs/research/PACKED_TERNARY_MATVEC_PERFORMANCE_REPORT.md)

### 2. 自适应表示法可具有条件优势

对自适应表示分层的研究已经确定了某些配置，在这些配置中，三进制表示的建模成本低于匹配的二进制替代方案。

这些优势取决于工作负载假设、元数据、转换成本和表示边界。

修正后的 H04-R02 研究保留了这些条件发现，同时明确将物理性能留待以后解决。

[阅读修正后的 H04-R02 发现](https://www.google.com/search?q=experiments/h04_r02_adaptive_representation/RESULTS.md)

### 3. 正确性并不等同于优化

最近的一项实验调查 T81-AIOPT-001 检查了四三进制模式匹配的多种表示形式。

其 M1 实现通过了广泛的本地正确性检查，但该实验工作负载可以简化为简单的序数比较。

该结果说明了为什么详尽的正确性测试对于评估计算优势来说仍然是不够的。

下一个问题不单单是另一种表示法是否可行。

而是所选的工作负载能否区分竞争算法之间的有意义差异。

[探索 T81-AIOPT-001](https://www.google.com/search?q=docs/research/aiopt/)

### 4. H04-R03 状态快照（2026-11-02）：正确性先于性能

H04-R03 匹配编解码器程序比较了有边界的表示法和访问替代方案，包括 B729-µ5 候选方案。其预注册协议和候选方案 A 的实现/审查在 [PR #677](https://github.com/t81dev/t81-foundation/pull/677)、[PR #679](https://github.com/t81dev/t81-foundation/pull/679) 和 [PR #680](https://github.com/t81dev/t81-foundation/pull/680) 中进行了跟踪。独立审查报告仅涉及正确性和协议接受度；截至 2026-11-02，PR #679 和 #680 仍然处于开启状态，C Phase 性能测量既未授权也未报告。在依赖此快照之前，必须刷新 PR 状态。

有效载荷长度相等是一种数学属性，并不是已经证明的延迟、能量或端到端收益。未宣称任何 H04-R03 性能优势。

### 5. 展示了有边界的跨环境执行（CPA-004/CPA-005）

**证据分类：有边界的确定性与可移植性，而非比较性能或全系统成熟度。** 以下结果涉及固定的程序和指定的执行环境；它们不适用于未测试的指令、工作负载、物理硬件或更广泛的架构。

跨环境架构（CPA）项目最近的研究表明，T81 的计算核心在不同的执行环境中始终如一地执行：

* **规范程序构件 (Canonical Program Artifact)：** 一个包含 27 个规范 13 字节记录的固化 351 字节规范程序（SHA-256 `b0649777cfa1c9e0fa1febb8bdfb1191c5cd3deea0d313791a4a32d5f207c80b`）测试了 17 条被认可的 TISC 指令子集。
* **跨环境等效性 (Cross-Profile Equivalence)：** 在三个托管的 T81VM 进程和三次新鲜的 AArch64 QEMU 裸机引导（在 UEFI `ExitBootServices` 之后）上的全新执行，在**所有 25 个观察边界**（初始状态 + 24 个指令步骤）上均与独立推导出的数学预言机相匹配。
* **全面的边界匹配：** 在所有 81 个寄存器值和标签、1,563 个逻辑内存字和标签、标志以及系统寄存器（R75–R80）上验证了等效性，在 PC=27、SP=283 处确定性地停机。
* **范围与快照：** 在存储库基础快照 `803075e9f7e36ed4b5318a8d2ddaacf62ae0a7e4` 上测试（带有提交在分支 `origin/experiment/cpa004-freestanding` 的提交 `b803bf916a1b1e44129f3a07abf96fa6103c51fc` 中的独立求值器和接受报告，以及本地 CPA-005 连续性记录）。
* **区别：** 证明跨环境执行的正确性证明了计算架构按预期运行；这**不是**三进制在性能、能量或硬件上优于二进制基准的证据。

### 6. 物理三进制计算仍然是一个开放性问题

软件模拟的三进制计算不等同于原生三进制硬件上的计算。

评估物理设备需要关于面积、能量、延迟、可靠性、传感、编码和外围成本的匹配证据。

目前的物理评估在缺乏足够的设备特征证据的地方仍然受阻。

T81 不会将缺失的证据解释为不可能的证明。

### 计算契约与执行配置文件

在 T81 架构中：

* **TISC（三进制指令集计算机）：** 作为核心计算指令契约，定义了操作码语义、64 位状态向量和确定性转换规则。
* **托管的 T81VM：** 作为用于用户空间开发、工具链、测试以及在传统宿主机操作系统（Linux、macOS、Windows）上进行确定性重放的托管执行配置文件。
* **独立的 Axion OS / TernaryOS：** 作为直接在硬件或虚拟机监控程序（例如 AArch64 QEMU）上运行的裸机执行配置文件，在没有用户空间 OS 依赖的情况下执行 TISC。
* **DAIOS（确定性 AI 操作系统）：** 仍然是用于高级自主智能体和 AI 运行时治理的独立、具有前瞻性的实验研究方向，不同于已实现的低级 TISC 执行引擎。

### 主要组件

| 组件 | 研究与架构角色 |
| --- | --- |
| **TISC** | 控制执行语义的计算指令契约 |
| **T81VM** | 用于虚拟机执行和确定性的托管执行配置文件（受[确定性表面注册表](https://www.google.com/search?q=docs/governance/DETERMINISM_SURFACE_REGISTRY.md)约束） |
| **Axion / TernaryOS** | 独立执行配置文件（裸机 AArch64 微内核/HAL）和副作用前策略授权 |
| **T81Lang** | 针对 TISC 的语言前端和编译基础架构 |
| **T81 Core** | 数值类型、容器和表示原语 |
| **CanonFS** | 内容寻址构件和完整性机制 |
| **DAIOS** | 针对确定性 AI 操作系统的独立目标架构提案 |
| **研究实验** | 假设检验、正确性验证和比较测量 |

这些组件具有不同的成熟度级别。一个工作的实现并不自动意味着一个经过验证的性能优势。

## 表示感知型自适应执行：一个开放的研究方向

历史上的 T81 手稿描述了一种综合宏愿：数值数据类型、TISC 执行语义、T81Lang/T81VM，以及 Axion 关于资源使用的仲裁决策。[历史 PDF 集合](https://www.google.com/search?q=docs/pdf/)保留了这些提案；它们报告的性能数据是**历史的、未经验证的主张**，而不是当前的实验结果。

这种宏愿的现代可证伪版本探讨系统是否可以针对**真实工作负载**在精确浮点数、低位、打包三进制和传统二进制表示法之间进行选择，在考虑到准确性、编码/解码、内存流量、调度和决策开销后实现净收益。项目必须区分：

* **T — 三进制特定机制：** 归因于三进制语义或物理三进制基底的优势，而不仅仅是不同的编码。
* **S — 软件表示选择：** 选择某种表示法带来的优势，可能可以通过二进制编码复现。
* **A — 算法路由：** 选择更好算法或执行路径带来的优势，与基数无关。

积极的 S 或 A 结果是有用的，但**并不**能确立 T。T81-AIOPT-001 M2 仍然是一个研究设计问题，而不是自适应三进制优势的授权证明。有关权威范围和门控，请查阅[AI 研究连续性](https://www.google.com/search?q=docs/ai-context/)和底层实验协议。

## 三个研究方向

T81 将其工作组织为三个互补的方向。

### 方向 R — 计算研究

研究替代表示法或计算架构是否能产生有用的优势。

主题包括：

* 平衡三进制算术与表示。
* 81 进制和高阶分组。
* 自适应表示选择。
* 打包低位计算。
* 内存与数据移动成本。
* 原生三进制硬件假设。
* 三进制 AI 推理与模型表示。

**成功意味着建立一个可辩护的结果，包括负面结果。**

### 方向 F — 基础工程

开发进行可靠实验和评估确定性计算所需的工具。

这包括虚拟机、语言工具链、构件身份、授权、重放和验证基础架构。

这些功能可能独立于三进制计算而发挥作用。

必须将其工程价值与特定基数优越性的主张分开评估。

### 方向 M — 研究记忆

保留每个结论背后的证据。

这包括源历史、实验协议、失败的尝试、更正、可复现性记录和未解决的问题。

被取代的结果仍然是历史记录的一部分。

数学模型不会被悄悄地提升为物理测量。

AI 生成的评估不自动等于独立验证。

[阅读主连续性章程 (Master Continuity Charter)](https://www.google.com/search?q=docs/research/continuity/MASTER_CONTINUITY_CHARTER_v1.0.md)

## 研究方法

T81 遵循证据至上的方法。

每个比较实验都应该回答五个问题：

1. **假设是什么？** 定义一个可证伪的命题。
2. **基准是什么？** 与功能等效、适当优化的传统替代方案进行比较。
3. **测量了什么？** 分别测量正确性、存储、延迟、吞吐量、能量和其他相关成本。
4. **局限性是什么？** 识别假设、硬件、工作负载范围、不确定性和未解决的依赖关系。
5. **什么结论是正当的？** 区分支持性、不支持性、无结论、受阻和未测试的结果。

项目还区分了：

**已实现 → 已测试 → 已测量 → 比较确立**

这些是不同的证据级别，不能互换标签。

实验结果不得宣称超出其证据支持范围的内容。

### Hanoi

T81 的历史早于当前的基金会存储库。

其最早的已知前身 **Hanoi** 通过 CWEB 文学编程探索了递归计算、三进制虚拟机结构、符号调度和依赖于工作负载的表示层。

该项目脱胎于对离散数学、算法、计算模型以及唐纳德·克努特（Donald Knuth）工作的研究。

随着时间的推移，研究扩展到了算术库、语言工具链、虚拟机、低位 AI 计算、确定性执行、治理和实验硬件。

一些历史设计是不完整的。一些假设被证明是不正确的。其他的则仍未被探索。

保留这一谱系的目的不是为了验证以前的每一个提案。

而是为了恢复激发它们的那些问题，并用更好的工具来检验这些问题。

## 当前研究优先级

该项目的当务之急是：

**1. 建立可靠的实验基准。**

在解释性能差异之前，验证等效的语义和独立可复现的行为。

**2. 识别具有区分度的工作负载。**

选择替代表示法会产生超出普通编码更改的合理、可测量后果的实验。

**3. 研究条件优势和 AI/ML 工作负载。**

研究表示密度、访问模式、转换成本、模型准确性或自适应策略改变结果的环境。与同样优化的二进制和算法路由基准进行比较。

**4. 保留物理硬件问题。**

将软件模拟的局限性与原生多值设备的成本和可行性区分开来。

**5. 维护实验基础。**

保持工具、规范、测试、溯源记录和治理机制足够可靠，以支持研究。

活跃的提案及其接受状态属于研究记录和拉取请求（PR）。它们出现在存储库中并不意味着获得正式批准。

## 参与贡献

T81 欢迎旨在提高科学理解、实现正确性、可复现性或文档水平的贡献。

特别有价值的贡献包括：

* 现有实验的独立复现。
* 更强的传统二进制基准。
* 数学反例和证明更正。
* 更小、更有区分度的实验协议。
* 跨平台正确性验证。
* 有证据支持的历史声明更正。
* 对研究基础架构有明确范围的改进。

在提出新的子系统之前，请确定它回答了哪个研究问题，以及什么证据能证明其有用性。

在修改研究构件之前，请阅读[贡献者路线图](https://www.google.com/search?q=docs/ROADMAP.md)、存储库治理指令和相关的实验协议。

## T81 不作出的声明

T81 目前不声称：

* 三进制计算对二进制计算的普遍优越性。
* 原生三进制硅芯片已被证明具有优越性。
* 集成的 T81 架构具有普遍的性能优势。
* 拥有在性能上优于强大固定策略或算法选择基准的经过验证的自适应 AI 优化器。
* 历史 PDF 案例研究数据构成了独立复现的测量结果。
* 三进制模型权重会从根本上加速 AI 推理。
* 确定性执行或策略实施需要三进制虚拟机。
* AI 生成的实验仅因测试通过就被独立验证。

这些边界对研究至关重要。

它们为未来的发现留下了空间，同时没有歪曲已经确立的事实。

## 问题依然悬而未决

出于令人信服的工程原因，二进制计算当今在物理和软件基础架构中占据主导地位。

这种主导地位并没有消除研究替代表示法、计算模型或未来硬件基底的价值。

T81 的目的在于确定这些替代方案在哪些地方有用——以及在哪些地方无用。

**我们不是先得出结论再寻找支持它的证据。**

**我们正在建立发现结论所需的实验基础。**
